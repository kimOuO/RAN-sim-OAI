# DT 環境串接 SMO(O1 adapter)可行性研究

日期:2026-09-28
範圍:目前運行中的 ransim-platform(CU/DU/RU/Physics/UE + e2adapter + run-orchestrator)要不要、怎麼接 O-RAN O1 介面給 SMO。

## 0. 結論

可行,而且有一條「幾天內可示範」的捷徑:**讓 DT 假扮 OAI gNB 的 telnet O1 模組,直接沿用 OAI 官方 o1-adapter 與 O-RAN SC 的 SMO**。
原因:o1-adapter 南向只認 telnet 上的 `o1 stats` JSON(4 個指令),而 DT 所有需要的資料(小區參數、PM、身分)都已在 CU/DU/RU 的 HTTP API 上;o1-adapter 自己就附了一支 Python telnet 假伺服器(`integration/telnet/servertest.py`)證明這條路官方就這樣測。

長期(完整 28.541 多小區、鄰區、天線、告警)要自己寫 O1 adapter(netopeer2 + sysrepo),形狀完全照現有 e2adapter 複製即可。

倉庫現況:repo 內沒有任何 O1/NETCONF/YANG/VES 程式碼;`o1_smo_plan/` 原本是空的;但多份規劃文件已預留 O1 掛點(見 §3)。

## 1. 官方規格與可用元件(已核對來源)

### 1.1 O-RAN O1 是什麼(WG10)
- O1 = SMO ↔ O-CU/O-DU/O-RU/near-RT RIC 的管理面,三種協定:
  - **CM**:NETCONF/YANG(3GPP TS 28.541 NRM:ManagedElement → GNBDUFunction/GNBCUCPFunction/GNBCUUPFunction → NRCellDU/NRCellCU/BWP/NRSectorCarrier/NRCellRelation…)
  - **FM/通知**:VES(HTTP JSON)`pnfRegistration`、`fault`、`heartbeat`、`stndDefined`
  - **PM**:TS 28.550 檔案式(3GPP measData XML,15 min 粒度,VES `fileReady` 通知,SMO 以 SFTP 取檔)或 PM streaming(websocket/GPB,OSC 尚未完整支援)
- 規格 ETSI 公版:ETSI TS 104 043(O-RAN O1 Interface Spec PAS)。
- 來源:WG10 頁 https://www.o-ran.org/technical-groups/wg10 ;ETSI TS 104 043 https://www.etsi.org/deliver/etsi_ts/104000_104099/104043/11.00.00_60/ts_104043v110000p.pdf ;OSC PM streaming 頁 https://lf-o-ran-sc.atlassian.net/wiki/spaces/OAM/pages/14680068

### 1.2 SMO 端:O-RAN SC OAM(docker compose 可起)
- 元件:Keycloak(identity)、OpenDaylight/SDNC(NETCONF client + RESTCONF 8181)、VES collector(`/eventListener/v7`)、Kafka(message router)、gateway、ODLUX 網頁、Node-RED。
- 部署需求(官方):Ubuntu 24.04、4 core、16 GB RAM、50 GB。本機目前 47 GB(已用 22 GB、可用 23 GB)、24 core、磁碟餘 84 GB:**放得下,但要留意記憶體**。
- 掛載 NF 的兩種方式:NF 送 VES `pnfRegistration`(SDNC 從 Kafka 收到後主動 SSH/TLS 連 NF 的 NETCONF 埠),或 SMO 用 RESTCONF `netconf-node-topology:create-device` 手動掛。
- 已知坑:第一筆 `pnfRegistration` 常遺失,官方叫重啟容器再送一次;OAI 教學也同樣註記。
- 來源:https://docs.o-ran-sc.org/projects/o-ran-sc-oam/en/latest/config-deploy.html ;https://lf-o-ran-sc.atlassian.net/wiki/display/SMO/How+to+test+the+O1+interface ;https://docs.ngkorefoundation.org/oran/smo-ric/osc-oam/

### 1.3 NF 假體:OSC NTS(sim/o1-interface)
- 純 NETCONF/YANG + VES 的 O-DU/O-RU 模擬器,資料是隨機生成,不接任何 RAN。適合**先把 SMO 端跑通**,不適合當 DT 的 O1。
- 來源:https://docs.o-ran-sc.org/projects/o-ran-sc-sim-o1-interface/en/latest/overview.html

### 1.4 OAI o1-adapter(最關鍵的可重用件)
已 clone 到 scratchpad 讀過原始碼(gitlab.eurecom.fr/oai/o1-adapter,最後 commit 2026-06-04「KPM management using NETCONF server」)。
- 架構:單一容器 = netopeer2-server + sysrepo + 3GPP/IETF YANG + `gnb-adapter`(C)。北向 NETCONF 1830 / TLS 6513、SFTP 122;VES 到 SMO collector v7。
- 南向:**只用 telnet**,每秒對 gNB 送 `o1 stats`,另外只會送 `o1 stop_modem`、`o1 bwconfig <MHz>`、`o1 start_modem`(`src/telnet/telnet.c` L587-655)。
- 載入的 YANG(30 支):`_3gpp-common-managed-element/-fm/-measurements/-filemanagement…`、`_3gpp-nr-nrm-gnbdufunction/gnbcucpfunction/gnbcuupfunction/nrcelldu/nrcellcu/bwp/nrsectorcarrier/nrfreqrelation/ep`、`ietf-inet-types`。
- CM 可寫入項:實際只處理 `bSChannelBwDL/UL` 變更(→ `o1 bwconfig`)與 gNBId(`netconf_data.c` L1708-1780);其餘 NRCellDU/BWP 屬性是唯讀映射。
- 節點型別:gNB / CU-CP / CU-UP / DU(`node_type.h`);每個 adapter 只建一個 `NRCellDU=0`(`netconf_data.c` L338)。
- PM:每 15 min 產生 3GPP measData XML,VES `fileReady`;支援的量測(`doc/tutorial.md`):DU 側 `DRB.MaxActiveUeUl/Dl`、`DRB.MeanActiveUeUl/Dl`、`RRU.PrbTotDl`、`DRB.UEThpUl/Dl`、`DRB.UEUnresVolThpUl/Dl`、`DRB.RlcPacketDropRateDl`;CU-UP 側 `DRB.PdcpSduVolumeUl/Dl`、`DRB.PdcpPduVolumeUl/Dl`。SMO 端可從 PERFMETRICJOB 勾選,寫入 InfluxDB。
- FM:內建告警 `internalConnectionLoss`(telnet 斷線 **MAJOR** / 恢復 NORMAL;README 表列 MINOR 為舊版)、下行負載超門檻警告(`config.json` alarms 區)。
- 設定檔 `integration/config/config.json.template`:`network.host/netconf-port/sftp-port`、`ves.url/heartbeat-interval/pm-data-interval`、`telnet.host/port`、`info.node-id/gnb-du-id/cell-local-id/managed-element-type`。
- 整合:`make run-o1-oai-adapter-smo(-telnet)` 會連 SMO 一起起(SDNC 2.7.0 映像);`integration/telnet/servertest.py`、`cu_servertest.py` 就是官方的 telnet 假 gNB。
- 已知限制(README + 第三方 K8s 部署經驗):adapter 必須掛在 DU 側(小區狀態在 DU);第一次 pnfRegistration 會漏;憑證明文。
- 來源:https://gitlab.eurecom.fr/oai/o1-adapter ;https://github.com/ontherays/oai-o1-adapter-O-cloud

### 1.5 OAI gNB 的 telnet O1 模組(本機 `/home/mitlab/openairinterface5g/common/utils/telnetsrv/telnetsrv_o1.c`,`DOC/telneto1.md`)
`o1 stats` 回傳 JSON 兩段:
- `o1-config`:`BWP.dl/ul[{isInitialBwp,numberOfRBs,startRB,subCarrierSpacing}]`、`NRCELLDU{ssbFrequency,arfcnDL,bSChannelBwDL,arfcnUL,bSChannelBwUL,nRPCI,nRTAC,mcc,mnc,sd,sst}`、`device{gnbId,gnbName,vendor}`
- `O1-Operational`:`frame-type,band-number,num-ues,ues[],load(%),ues-thp[{rnti,dl,ul} kbit/s]`
`o1 config` 只允許在 L1 停止時依固定順序寫 ssbFrequency/arfcnDL/bSChannelBwDL/numberOfRBs/startRB;`o1 bwconfig 20|40|60|100`;`stop_modem`/`start_modem`。
**這份 JSON 就是 DT 要模仿的合約。**

## 3. 三條路線比較

| | A. telnet 假面 + 原版 o1-adapter | B. 自寫 O1 adapter(fork o1-adapter 或 Python + sysrepo) | C. NTS 模擬器 |
|---|---|---|---|
| 工作量 | 1 支 Python telnet server(~300 行)+ compose | 數週:YANG 樹、sysrepo callback、VES、PM 檔、告警 | 0(但與 DT 無關) |
| SMO 看到什麼 | 每 DU 一個 ME、1 個 NRCellDU、BWP、gNB id;PM 10+4 項;告警 2 種 | 完整 28.541:多小區、NRCellRelation、NRSectorCarrier、天線/傾角、自訂告警、190 計數器 | 隨機資料 |
| CM 寫入 | 只有頻寬(bwconfig)與 gNBId | 任意(A3、PRB、功率、tilt、鎖小區…) | 無 |
| 多小區 | 一顆 adapter 只 1 cell → 需「每 cell 一顆 adapter,把 cell 假裝成 DU」 | 原生 | n/a |
| 適合 | 展示、驗 SMO 通路、報告截圖 | 正式交付 / rApp 研究 | 先把 SMO 裝好 |

建議順序:**C(半天)→ A(2–3 天)→ 視需求 B**。

## 4. 路線 A 具體設計

新增容器 `o1-telnet-facade`(或直接加進 e2adapter 映像),每個 gNB/DU 實例一份,監聽 `9090+slot`:
1. `o1 stats`:呼叫 CU `E2/NodeInfo/read` + `CellConfig` + DU `MacScheduler/get_runtime_phys` + `E2/E2FullReporter/read`,組成 §1.5 的 JSON。對應:
   - `nRPCI`←pci;`arfcnDL/UL`←`nr_arfcn_from_ghz(frequency_ghz)`;`bSChannelBwDL/UL`←bandwidth_mhz;`numberOfRBs`←n_prb;`subCarrierSpacing`←30;`nRTAC`←0xa000;`mcc/mnc/sst`←env;`sd`←16777215;`gnbId`←gnb_du_id;`gnbName`←meid
   - `num-ues/ues`←`ue_status[]`;`load`←`RRU.PrbTotDl`;`ues-thp[].dl/ul`←`DRB.UEThpDl/Ul`(kbit/s)
2. `o1 stop_modem` / `start_modem`:對應 `MacCellController/disable|enable`(或 CCC administrativeState LOCKED/UNLOCKED),讓 SMO 的鎖小區流程有實效。
3. `o1 bwconfig N`:DT 目前 n_prb 全域寫死,先回 OK 並記錄,或在 DU 加一個 runtime `bandwidth_mhz` 設定點。
4. o1-adapter 以 `info.node-id = meid`、`gnb-du-id`、`network.netconf-port = 1830+slot` 起一顆;`ves.url` 指向 SMO。
5. orchestrator `ROLES`/`plan_instances` 加 `o1adapter` 角色,與 e2adapter 同方式 spawn。

網路:adapter 與 e2adapter 一樣走 host network(SMO 要能反連 NETCONF 埠與 SFTP);SMO 若放在 RIC 主機(10.3.0.71)那側,需開 1830+slot、122+slot 入站。

## 5. 路線 B 增補項(若要正式交付)
- YANG:沿用 o1-adapter 的 30 支 3GPP Rel-18 模型,擴成多 `NRCellDU`/`NRCellCU`、`NRCellRelation`、`NRSectorCarrier`(power/tilt),天線用 O-RAN WG4 MP-YANG(`docs/MIMO/antenna_spec_v2.md` 已引用 v21.01)。
- CM 寫入 → 現有 HTTP set 端點;需先把 `HO_*`、`ANR_*` 從 env 改成 runtime 可設。
- PM:由 `RunPmSnapshot`/FullKPM 聚合成 15 min(或 5 min)measData XML + `fileReady`,直接用 28.552 名稱;190 計數器裡 96 real 的先放。
- FM:定義告警字典(比照 `dictionary/oai-alarm-dictionary.xml`):DU 失聯、RLF 率超標、HO 失敗率、PCI confusion、cell LOCKED、E2 link down;VES `fault` raise/clear。
- 這正好補上 `ne_and_parameters.md` L155-165 所說「拆 NE config 之後 O1 才有地方掛」。
