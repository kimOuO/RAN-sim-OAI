## 2. 對接架構(定案)

```
DT 主機 10.3.0.217                                        smo-master 10.3.0.204
┌──────────────────────────────┐                          ┌──────────────────────────┐
│ CU/DU/RU (HTTP 8101/8102/8103)│                          │ SDNC/SDNR 2.6.1          │
│        ▲ HTTP                 │  NETCONF/SSH 1830+slot   │   ▲ mount(反連)  30266 call-home(備援)
│ o1-telnet-facade :9090+slot  │◄─────────────────────────│   │                      │
│        ▲ telnet `o1 stats`    │                          │ VES collector :30417 ────► Kafka
│ o1-adapter (netopeer2/sysrepo)│─── VES pnfReg/heartbeat/ │   │                      │
│   NETCONF :1830+slot          │    fault/fileReady ─────►│   ▼                      │
│   SFTP    :122+slot           │◄─── dfc 以 sftp 取 PM 檔 │ dfc → MinIO → xml2json → pmlog → InfluxDB2
└──────────────────────────────┘                          └──────────────────────────┘
```

每個 gNB(每 run)一組 facade + adapter,ME 名稱 = meid(例 `gnb_208_095_000e00`),由 run-orchestrator 與 e2adapter 同方式 spawn,host network。

## 5. 聯調步驟
1. **連通**:DT 起 adapter 後,SMO 端 `nc -zv 10.3.0.217 1830 122`(主機與 sdnc pod 內各一次)。
2. **註冊**:adapter 送 pnfRegistration;SMO 端 `kubectl exec kafka-client -- kafka-console-consumer --topic unauthenticated.VES_PNFREG_OUTPUT` 看到事件;ODLUX 出現 `gnb_208_095_000e00`,狀態 connected。第一筆常漏,漏了重啟 adapter。
3. **CM 讀**:RESTCONF `GET .../topology-netconf/node=<meid>/yang-ext:mount/_3gpp-common-managed-element:ManagedElement=<meid>` 對照 DT CellConfig(PCI/ARFCN/頻寬/PLMN/TAC)。
4. **FM**:停 DT 的 DU 容器 → SMO 收 `softmodem-o1adapter-connected` MINOR;恢復 → CLEAR(ODLUX Fault 頁)。
5. **PM**:`pm-data-interval` 先縮到 60 s;看 `VES_NOTIFICATION_OUTPUT` 有 fileReady → dfc log 取檔成功 → MinIO `ropfiles` 出現檔案 → `pmreports` topic → InfluxDB2 `pm-logg-bucket` 查到 sourceName=meid。
6. **CM 寫**(選配):ODLUX 改 `bSChannelBwDL` → facade 收到 `o1 bwconfig`。
7. **多 run**:開兩個 run,ODLUX 出現兩個 meid,埠各自不同。
