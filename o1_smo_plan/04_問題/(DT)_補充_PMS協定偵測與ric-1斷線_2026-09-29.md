# (DT) 補充:PMS 對 10.3.0.71 a1mediator 的協定偵測、ric-1 每小時斷線

日期:2026-09-29。來自 DT 端,綜合 RIC 團隊第二輪回覆。**不改變這一階段的執行內容**,只是先講清楚兩個之後會碰到的點。

## 1. a1mediator 3.2.3 與 PMS 2.11.0 的格式差
- a1mediator 3.2.3 只有 `/A1-P/v2/…` 路徑,policy type 回應欄位是 `create_schema`,沒有 `policySchema`(RIC 團隊查 swagger 確認)。
- PMS 2.11.0 協定偵測先試 `/A1-P/v2/policytypes`,會把它當 STD_V2 去讀 `policySchema` → 有 type 時 schema 讀不到。你們的 a1med-proxy 正是補這個差。
- **現在 type 清單是 `[]`,直接登錄 `http://10.3.0.71:30183` 沒有風險。** 日後做 20008 時再把 a1med-proxy 的 UPSTREAM 改指 10.3.0.71:30183、ric-dt-71 baseUrl 改指 proxy 即可。

## 2. configmap 與 API 不同步的實證
- `policymanagementservice-data-configmap` 裡沒有 `ric-es-proxy`(只有 ric1–6 + nearrtric1),代表它是 API PUT 加的、Pod 重啟會消失。新增 ric-dt-71 請同步改 configmap(你們已提到)。
- 該 configmap 含 controller1 明文密碼;我方看到但不記錄。建議之後改 secret。

## 3. ric-1 每小時 :28:15 斷線
- RIC 團隊查他們的 o1mediator 0.6.4 / netopeer2 1.1.78:無任何每小時動作、無 idle-timeout。
- 你們 SDNC log 的 ric-1 事件固定 hh:28:14–15,吻合 **SSH rekey**(libssh/OpenSSH 預設每 1 h 重協商,某些組合 rekey 失敗 server 主動關)假說;另一可能是你們同機 o1mediator 的 liveness/重啟。
- 建議:掛上 ric-dt-71 後記下掛載時刻,若之後每小時在同一偏移斷線 → 確認是 rekey;SDNC keepalive 120 + 自動重連可掩蓋,不阻塞聯調。可順手看一下你們 o1mediator pod 的 restart 次數與 liveness 設定排除 (b)。
