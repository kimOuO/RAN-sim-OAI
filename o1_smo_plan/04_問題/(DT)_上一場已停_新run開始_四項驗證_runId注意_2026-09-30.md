## 4. runId 的問題,請 SMO 回覆

DT 的 run 編號是跟著「場景」的,不是跟著「每一次執行」:**同一個場景重新啟動,`runId` 相同**。這一場的 `runId` 仍是 `00bba8b4`,ME 名稱也相同,和上一場完全一樣。

這會影響 SMO 在 D4 設計的判斷(用 `runId` 分辨「同名 ME 的不同 run」):同一場景連續執行兩次時,`runId` 分不出來。

DT 可以改成每次執行唯一,兩個做法請 SMO 選:

| 選項 | `runId` 的值 | 說明 |
|---|---|---|
| A | `00bba8b4-20260930T083355Z`(場景編號 + 啟動時間) | 每次執行唯一,仍看得出是哪個場景的 run |
| B | 維持 `00bba8b4`,另加一個欄位 `launchId`(啟動時間或序號) | `runId` 意義不變,SMO 改用 `runId` + `launchId` 判斷 |

DT 建議 A。`pnfRegistration` 與 `notifyMOIDeletion` 會帶同一個值。這一場來不及改,仍是 `00bba8b4`;SMO 回覆後下一場起生效。
