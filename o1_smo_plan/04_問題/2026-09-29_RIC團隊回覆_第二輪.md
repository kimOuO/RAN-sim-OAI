# RIC 團隊回覆(第二輪)—— o1mediator 每小時斷線、a1mediator 格式

日期:2026-09-29。來源:`anr_xapps`。狀態:已吸收進 `01_計畫/RIC登錄SMO_計畫_v1_2026-09-29.md` §8。

1. 10.3.0.71 的 o1mediator 0.6.4(netopeer2 1.1.78)沒有任何每小時動作:24 h 無 session/timeout/close 字樣、無 cron、pod 自 9/24 未重啟;只有 TCP keepalive,無 session idle-timeout / hello-timeout。SMO 那邊 `ric-1` 每小時 :28:15 的 `End of input` 不是 netopeer2 預設造成。兩個方向:(a) **SSH rekey**(libssh/OpenSSH 預設 1 h 或 1 GB 重新協商,netopeer2 與某些客戶端 rekey 會失敗、server 主動關;時間偏移 = 掛載時刻);(b) SMO 那台 o1mediator 的 liveness probe / 重啟。掛上 ric-dt-71 後若同樣每小時斷且偏移 = 掛載時刻,即為 (a)。
   - 我方旁證:SMO 的 SDNC log 裡 `ric-1` 事件都落在 **hh:28:14–15**,與 (a) 的「固定偏移」一致。
2. **修正**:a1mediator 3.2.3 只有 `/A1-P/v2/…` 路徑,policy type 回應欄位是 `create_schema / description / name / policy_type_id`,**沒有 `policySchema`**。PMS 若靠路徑偵測會把它當 STD_V2 去讀 `policySchema` → 對不上。a1med-proxy 把 `create_schema` 複製成 `policySchema` 正是補這個差 → **登錄 10.3.0.71 時,一旦有 policy type,proxy 仍需要**(UPSTREAM 改指 10.3.0.71:30183)。目前 type 清單 `[]`,兩種 adapter 同步都得空清單,不會判 UNAVAILABLE,**先登錄沒有風險**。
