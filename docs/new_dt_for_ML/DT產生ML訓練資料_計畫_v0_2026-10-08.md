## 1. 背景

ran_dt 的方法為「拓樸 + UE 位置 → 建立服務 / 干擾關係 → 效能模型推論 KPI → 與實網比對並校正」。其效能模型輸入為 `X[B, T, F=16, M, N]`,輸出為 `Y[B, T, 4, M, N]`(RSRP、SINR、SNR、Throughput);目前模型為 3GPP 公式替身,「實網」為真值參數加雜訊之假資料,仿真率 53% → 91% 僅證明校正流程可行。

本平台具備射線追蹤通道(Sionna)與完整 RAN 協定行為(CU / DU / RU / UE),可作為「準真實環境」,產生具物理一致性之 X 與 Y,取代假資料。

## 2. 目標

1. DT 端離線產生符合 ran_dt 張量格式之訓練資料集(X、Y、mask)。
2. 資料涵蓋足夠之拓樸、負載、移動與事件多樣性,可供 UE–Cell 二分圖 GNN 等模型訓練。
3. 提供仿真率計分工具(服務 Cell 一致、RSRP ±3 dB、SINR ±3 dB、Throughput ±10%),以未參與訓練之場景驗收模型。
4. 計分工具同時可用於日後「DT 對實網」之比對。

## 3. 範圍

**納入**
- 資料匯出器、批次場景產生、資料集組裝、仿真率計分。
- 既有歸檔資料之初步試作。

**不納入**
- 核心網(N2 / N3、UPF 選擇、切片、傳輸延遲)之模擬。
- 模型架構之研究與調參(本計畫交付資料與計分工具,模型訓練另案)。
- 任何經 E2 / RIC 之資料流。

## 4. 約束

| # | 約束 | 影響 |
|---|---|---|
| K1 | UE 座標不進入 E2 / RIC / I-5(使用者決定) | 距離、夾角特徵僅於 DT 內部離線計算;資料集不經 RIC,不對外介面輸出 |
| K2 | 每場 CU / DU / RU 資料庫於停場時刪除 | 所需細粒度資料須於歸檔資料庫保留,或於停場前匯出 |
| K3 | 以場景時間對齊 | X、Y 一律以 `sim_time_ms` 對齊,不使用牆鐘時間(倍速執行時兩者不同) |
| K4 | 主機容量:no_ric、cache、10× 約 8 場同時;live 同時 1 場 | 批次產生採 no_ric + cache;未預算場景須先預算 |
| K5 | 不影響原有功能 | 匯出器為新增元件,預設關閉,不改既有 KPM / E2 / O1 行為 |

## 5. 資料定義

### 5.1 時間與維度

- CLK:ran_dt 為 2 s。DT 歸檔 KPM 視窗為 1 s(`run_kpm_sample.sim_time_ms`,每 500–1000 ms 一筆),以 2 s 彙整;CLK 長度設為參數,保留 1 s 版本。
- M:場景內 UE 清單,順序固定;不在場之 UE 補 0,`mask = 0`。
- N:場景內 Cell 清單(跨 gNB),順序固定。

### 5.2 輸出 Y(真值)

| 指標 | 範圍 | DT 來源 | 現況 |
|---|---|---|---|
| RSRP | 每格(UE × 每個 Cell) | 服務 Cell:`per_ue.rsrp_dbm`;其他 Cell:`per_ue.neighbor_cells_json[].rsrp_dbm` | 已歸檔;**待確認**鄰區清單是否涵蓋全部 Cell(含跨 gNB),若僅含量測門檻以上之 Cell,需自 RU 補匯出全 Cell RSRP |
| SINR | 服務 Cell | `per_ue.sinr_db`(含干擾與 EVM 上限) | 已歸檔 |
| SNR | 服務 Cell | RSRP − 雜訊底線換算,或自 RU 匯出 | 需補(換算即可) |
| Throughput | 服務 Cell | `per_ue.throughput_dl_mbps` / `throughput_ul_mbps` | 已歸檔 |

非服務 Cell 之 SINR / SNR / Throughput 記為 NaN(同 ran_dt)。

### 5.3 輸入 X(16 特徵)對照

| # | 特徵 | 層級 | DT 來源 | 現況 |
|---|---|---|---|---|
| 0 | relation(0 無 / 1 服務 / 2 干擾) | UE×Cell | `per_ue.serving_cell`;干擾 = RSRP ≥ −120 dBm 之非服務 Cell | 可推導 |
| 1 | allowed | UE×Cell | 無核心網 | 不提供(固定 1 或移除) |
| 2 | dist_3d_m | UE×Cell | UE 位置 × RU 位置 | UE 位置由場景路徑點依場景時間內插;RU 位置於 registry |
| 3 | h_angle_deg | UE×Cell | UE 位置 × RU 方位角 | 同上 |
| 4 | v_angle_deg | UE×Cell | UE 位置 × RU 高度 / 下傾角 | 同上 |
| 5 | los | UE×Cell | Sionna 路徑資訊(是否存在直射路徑) | **需補**:自通道快取或 live 計算匯出 |
| 6 | clutter_db | UE×Cell | 射線追蹤路徑損耗 − 自由空間路徑損耗 | **需補**:由 RSRP、發射功率、天線增益與距離推算,或自通道匯出 |
| 7 | transport_ms | UE×Cell | 無核心網 | 不提供 |
| 8 | tx_re_dbm | Cell | Cell 發射功率 / RE 數 | registry,可換算 |
| 9 | freq_ghz | Cell | Cell 中心頻率 | registry |
| 10 | n_prb | Cell | DU PRB 數 | registry |
| 11 | scs_khz | Cell | DU numerology | registry |
| 12 | dl_ratio | Cell | TDD 樣式 | registry,換算 |
| 13 | cell_load | Cell | 上一 CLK 之 `per_cell.prb_pct_dl` | 已歸檔 |
| 14 | request_mbps | UE | 場景 UE 流量設定(依時段) | registry |
| 15 | sst | UE | 無切片;以 `per_ue.qos_5qi` 替代 | 已歸檔 |

**擴充特徵(選用,ran_dt 無)**:CQI、MCS(`mcs_dl` / `mcs_ul`)、MIMO rank(`mimo_rank`)、配置 PRB(`rb_width_dl`)、RSRQ、UL SINR、RLC 延遲。可作為額外輸入或額外預測目標。

### 5.4 事件標註(選用)

換手(`run_handover_event`)、RLF、重建、節能關 Cell 等事件,以 `(sim_time_ms, ue)` 標註於 mask 以外之旁表,供分析模型於事件附近之誤差。

## 6. 架構

```
registry(場景、拓樸、UE 路徑、流量)──┐
歸檔 DB(run_kpm_sample、run_handover_event)─┤
通道資料(LOS、路徑損耗;新增匯出)──────┘
            │
            ▼
   ml_export(DT 端離線工具,新增)
     1. 依 scene_run 讀取上述資料
     2. 以 sim_time_ms 對齊、彙整為 CLK
     3. 計算 UE 位置與幾何特徵(僅 DT 內部)
     4. 組成 X[T,F,M,N]、Y[T,4,M,N]、mask[T,M]
            │
            ▼
   dataset/<scene_run>.npz + manifest.json(場景參數、特徵版本、CLK)
            │
            ▼
   make_windows(T_in, T_out)→ 訓練 / 驗證 / 測試(以場景切分)
            │
            ▼
   fidelity():四項命中率與仿真率
```

- 工具置於 DT 端(建議 `tools/ml_dataset/`),以 Python 腳本實作,讀取 registry 與歸檔資料庫,不需改動執行中服務。
- 僅「全 Cell RSRP」與「LOS / 路徑損耗」可能需於 RU 或 Physics 端新增匯出點,屬新增功能,預設關閉。

## 7. 場景多樣性設計

| 維度 | 變化範圍(初稿) |
|---|---|
| 場域 | 走廊(室內掃描)、OSM 戶外(ntust)、其他既有場域 |
| 拓樸 | gNB 1–3、每 gNB Cell 1–3;位置、方位角、下傾角、發射功率隨機擾動 |
| 天線 | 1×1、2×2、8×8 等既有預設 |
| UE | 數量 5–40;路徑樣式(一般走動、通勤人流、會議室、尖峰);速度 0.8–1.5 m/s |
| 負載 | 輕量 50–300 kbps 至重度 0.5–5 Mbps;含空載與飽和 |
| 事件 | 節能關 Cell、Cell 鎖定、高負載換手 |
| 長度 | 每場 10–20 分鐘場景時間 |

- 以場景編輯器之隨機產生功能與 registry API 批次建立,種子固定以利重現。
- 訓練 / 驗證 / 測試以**場景**為單位切分(建議 70 / 15 / 15),另保留一組未見場域作為泛化測試。

## 8. 執行階段

| 階段 | 內容 | 產出 | 預估 |
|---|---|---|---|
| P0 盤點 | 確認 `neighbor_cells_json` 是否涵蓋全部 Cell(含跨 gNB);確認歸檔保留期限與容量;確認 UE 位置內插與 UE 實際位置一致 | 盤點紀錄 | 0.5 天 |
| P1 試作 | 以既有歸檔資料(目前約 94 萬筆 KPM 樣本)與既有場景,完成 ml_export 第一版;特徵 0、2–4、8–15 與 Y 之 RSRP / SINR / Throughput | 第一批 npz、資料品質報告 | 2 天 |
| P2 補匯出 | 全 Cell RSRP(若 P0 不足)、LOS、路徑損耗、SNR | RU / Physics 匯出點(預設關閉)、特徵 5、6 | 2–3 天 |
| P3 批次產生 | 場景產生腳本、no_ric + cache 批次執行(停用 O1)、自動匯出 | 首批 100 場資料集 | 依主機:10× 約 8 場同時,每場 10 分鐘場景時間約 1 分鐘,含啟停約 2–3 分鐘 |
| P4 計分 | fidelity() 實作;以簡單基線(3GPP 公式)計分,建立對照 | 基線仿真率報告 | 1 天 |
| P5 交付 | 資料集格式文件、manifest 規格、使用範例 | `docs/new_dt_for_ML/` 文件與範例 | 0.5 天 |

## 9. 驗收

1. 任一 scene_run 可產出 X、Y、mask,維度與 manifest 一致,無時間錯位(抽樣比對歸檔原始值)。
2. Y 之服務 Cell RSRP / SINR / Throughput 與歸檔值逐筆一致。
3. 幾何特徵抽樣核對:UE 位置內插與 UE 容器回報位置誤差 < 0.5 m。
4. 批次執行 100 場,成功率 ≥ 95%,失敗場景有原因紀錄。
5. fidelity() 對同一資料輸入得 100%;對 3GPP 公式基線產出四項命中率。

## 10. 風險

| 風險 | 說明 | 對策 |
|---|---|---|
| 鄰區 RSRP 不完整 | 量測報告可能僅含門檻以上之鄰區 | P0 確認;不足則 RU 補匯出全 Cell RSRP |
| 模型學到模擬器特性 | 資料來自同一模擬器,模型可能僅模仿 DT 之偏差 | 以實網少量資料微調(ran_dt 之 sim-to-real);保留未見場域測試 |
| 主機資源 | 批次執行與日常測試、RIC 聯測競用 CPU | 批次於離峰執行;執行前確認無 RIC 測試 |
| O1 隨 no_ric run 啟動 | 目前 no_ric run 亦會起 O1 並向 SMO 註冊 | 批次執行停用 O1(需確認開關),避免於 SMO 產生大量 ME |
| 資料量 | 每場 300 CLK × M × N × 16,百場級可達數 GB | 以 float16 / 壓縮 npz 儲存;manifest 記錄版本 |
