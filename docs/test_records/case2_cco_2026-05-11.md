## 1. 測試目標

驗證 sim ↔ RIC 第二次完整 closed-loop, 動作為 Style 3 / Action 1 control_handover:

```
sim KPM (per-cell PRB) → RIC xApp cco-01 strategy 偵測 cell PRB imbalance
   → 選 hot cell 邊緣 UE (min RSRP) → fire RIC_CONTROL_REQUEST style=3 action=1
   → sim e2adapter recv → CU dispatch → execute_f1_handover
   → DB UPDATE UeContext.serving_cell + F1AP UE Context Modification
   → DU 改 serving_cell, UE 真正 migrate
```

CCO trigger 4 個條件 (對齊 `intents-interface.md §4.2`):
- `hot_cell_PRB` > 0.85
- `cold_cell_PRB` < 0.30
- `imbalance_gap` > 0.30
- sustain 5s + GRACE 60s

## 4. Fire 事件 — 兩階段

### 4.1 階段 A: A3 rollback (04:30:36 ~ 04:43:41 UTC)

RIC strategy 共 fire 10 次 control_handover, sim 都成功 execute, 但 sim CU 自帶 A3
evaluator 1~5 秒內 fire back, 100% rollback.

```
T=04:30:36  RIC HO ngap=76725958 → c2     sim execute ✓  →  A3 rollback ⚠
T=04:31:11  RIC HO ngap=1672764947 → c2   sim execute ✓  →  A3 rollback ⚠
T=04:31:46  RIC HO ngap=1672764947 → c2   sim execute ✓  →  A3 rollback ⚠
T=04:32:21  RIC HO ngap=1672764947 → c2   sim execute ✓  →  A3 rollback ⚠
T=04:32:56  RIC HO ngap=545203771 → c2    sim execute ✓  →  A3 rollback ⚠
T=04:33:31  RIC HO ngap=1707264170 → c2   sim execute ✓  →  A3 rollback ⚠
T=04:34:06  RIC HO ngap=545203771 → c2    sim execute ✓  →  A3 rollback ⚠
T=04:35:59  RIC HO ngap=529712861 → c2    sim execute ✓  →  A3 rollback ⚠
T=04:36:34  RIC HO ngap=529712861 → c2    sim execute ✓  →  A3 rollback ⚠
T=04:37:09  RIC HO ngap=529712861 → c2    sim execute ✓  →  A3 rollback ⚠
```

#### Root cause

- UE 物理位置都在 east 200m cluster (5m offset 內變異很小)
- HO 到 c2 (west beam) 後, UE 對 c2 從背面接收, RSRP 從 -68 dBm 跌到 -110 dBm 級
- c0 vs c2 RSRP 差約 40 dB
- A3 condition `(nb_rsrp - hys) > (serving_rsrp + offset)` 用 offset=0.5 dB 太鬆
- A3 立刻認為「c0 RSRP 比 c2 高太多, 應該回去」→ fire back

#### Quick fix (AK9)

`HO_A3_OFFSET_DB=100`: A3 condition 要求 neighbor 比 serving 強 100 dB 才 trigger
→ 任何 RSRP 差距都不會達標 → A3 evaluator effectively disabled

### 5.3 物理意義

- HO 走 1 個 c0 UE 即釋放 cell 將近一半 PRB (PF scheduler 重新公平分)
- c2 收到 1 個 active UE (demo_0517 仍是 30 Mbps demand), 重新 active, PF 給它跟其他 idle UE 50% 共享
- 整體 load 從 c0 集中 → 兩 cell 均勻

## 7. Limitations / 已知問題

| 項目 | 影響 | 後續 |
|:---|:---|:---|
| **sim A3 與 RIC HO 衝突** | RIC HO 物理上不 justified 時, A3 立即 rollback | (a) 場景: split cluster 加 edge UE; (b) sim CU 加 "RIC HO grace period" (HO 後 30s suppress A3) |
| **RIC edge UE selection 簡化** | min(serving RSRP) 隨機選 (UE 物理位置一致) | RIC C5 task: 補 neighbor RSRP 從 KPM Indication 解出 (sim 端 already wire) |
| **c2 PRB post-HO 升到 50%** | sim PF scheduler 對 idle UE 仍 measurement-only PRB | 預期 behavior, 對 demo 不影響 |
| **A3 OFFSET=100 是 hack** | demo 結束後 sim 失去自動 mobility | demo 後改回 0.5 (default) 或加 HO_A3_ENABLED env flag |

## 8. Lessons learned

### 8.1 修了什麼 (Case 1 → Case 2 路上)

| Fix ID | 改了什麼 |
|:---|:---|
| **AK7** | Sionna engine 取消 per-gnb path_gain 聚合 — sectored cells 各自 emit 自己 path_gain, 對應 azimuth + UE 位置真實 differentiation |
| **AK8** | setup_multi_ue cluster center 改成 c0 east + c2 west 對齊 cell beam |
| **AK9** | HO_A3_OFFSET_DB=100 暫時關 sim A3, 讓 RIC HO 不被 rollback |

### 8.2 對未來 Case 3 ES 的 implication

- **多 cell + 部分 idle** 拓樸已 demo 可行 (c1/c3 沒 UE 不發 indication)
- **idle 時 PRB = 0** 已 demo (c2 4 UE idle, PRB 0%)
- **ES 5-min sliding window** RIC strategy 要實作 (現在只有 short-window vol detector)
- **ES action 兩段式** (HO out + PRB quota squeeze) — 兩個 sim chain 都已 verified, 組合 demo 應該可行

### 8.3 真實 5G 對比

- 真實 RIC CCO 選 edge UE: 用 SON / MRO algorithm 同時看 serving + neighbor RSRP/RSRQ
- 真實 HO 物理上是 UE 真的移動位置 (車輛 / 行人) 自然進入 cold cell beam, A3 不會 rollback
- 我們 sim 用 static position, RIC simplified edge selection → 必須關 A3 才能 demo. Production 不需要 (real mobility 自然對齊)
