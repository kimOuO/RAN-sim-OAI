## 1. 測試目標

驗證 sim ↔ RIC 第三次完整 closed-loop, 動作是 **multi-PDU 兩段式**:

```
Stage 1 — Squeeze:
  RIC strategy 偵測 c2 持續 idle (vol < 1MB sustained)
  → Step 1: 連續 fire 4 個 control_handover (Style 3/1) 把 c2 殘留 UE 全 HO 到 c0
  → Step 2: fire control_slice_level_prb_quota (Style 2/6)
              min=0, max=5, dedicated=0 — 壓 cell PRB 配額到極小

Stage 2 — Release (自動觸發, ~30s 後):
  RIC strategy 偵測 ES condition 不再成立 (c0 vol 高 > 1.5MB)
  → fire control_slice_level_prb_quota (Style 2/6)
              min=10, max=100, dedicated=0 — 解封 PRB cap
```

ES trigger 條件 (對齊 `intents-interface.md §4.3`):
- `RRU.PrbTotDl` mean < 0.10 (5min sliding window)
- `DRB.PdcpSduVolumeDL` mean < 1MB (5min sliding window)
- 兩條件同時成立才算 cell idle

## 8. Lessons learned

### 8.1 Multi-PDU sequence 行為驗證 (本案首次)

Case 1 / 2 都是 single PDU fire. Case 3 ES 在 < 1 秒內 fire **6 個 PDU** (4 HO + 1 squeeze + 1 release):
- sim e2adapter SCTP socket recv loop 能連續處理多 PDU
- CU dispatch 每 PDU 都獨立 process (per-UE F1 Handover + per-cell quota)
- 無 race condition

### 8.2 Sim state machine 對齊 RIC

RIC `in_es_squeeze=True` ↔ sim DU MacScheduler quota state (in-memory dict). 兩端獨立追蹤, 透過 RC Control + KPM Indication sync, 不會 desync。

### 8.3 對未來 Case 4+ implication

- **Per-cell scope squeeze** 需 sim 跟 RIC encoder 雙方同時改 PDU schema (加 cell_id field, 不止 meid)
- **ES → IM 切換 priority** 已內建 IM-block 30s, 但 demo 沒 cover 這條 path (cooldown 過了沒繼續觀察)
- **多 case 串接 demo** (e.g. ES squeeze 後手動拉 c0 traffic → IM trigger): 設計過但本次 demo 未串
