## A. TS 38.141-1 — §3.1 天線／TAB 相關定義

### [1411-001] antenna connector / BS type 1-C / 1-H / 1-O / 2-O
- 出處：TS 38.141-1 V19.5.0 §3.1, p.24
- 原文：
> antenna connector: connector at the conducted interface of the BS type 1-C
>
> BS type 1-C: NR base station operating at FR1 with requirements set consisting only of conducted requirements defined at individual antenna connectors
>
> BS type 1-H: NR base station operating at FR1 with a requirement set consisting of conducted requirements defined at individual TAB connectors and OTA requirements defined at RIB
>
> BS type 1-O: NR base station operating at FR1 with a requirement set consisting only of OTA requirements defined at the RIB
>
>     NOTE: BS type 1-O conformance requirements are captured in TS 38.141-2 [3] and are out of scope of this specification.
>
> BS type 2-O: NR base station operating at FR2 with a requirement set consisting only of OTA requirements defined at the RIB
- 型別：`bs_type: enum {1-C, 1-H, 1-O, 2-O}`
- 說明：1-C 的傳導參考點是 antenna connector；1-H 是 TAB connector（傳導）＋ RIB（OTA）。1-O／2-O 只有 OTA，在 38.141-2。

### [1411-002] TAB connector / transceiver array boundary
- 出處：TS 38.141-1 V19.5.0 §3.1, p.26
- 原文：
> TAB connector: transceiver array boundary connector
>
> transceiver array boundary: conducted interface between the transceiver unit array and the composite antenna
- 說明：TAB = 收發單元陣列與複合天線之間的傳導介面（對應 38.104 的 TRXUA→TAB→RDN→AA 鏈，見 `01_38901_38104.md` [104-031]）。

### [1411-003] TAB connector TX min cell group
- 出處：TS 38.141-1 V19.5.0 §3.1, p.26
- 原文：
> TAB connector TX min cell group: operating band specific declared group of TAB connectors to which BS type 1-H conducted TX requirements are applied.
>
>     NOTE: Within this definition, the group corresponds to the group of TAB connectors which are responsible for transmitting a cell when the BS type 1-H setting corresponding to the declared minimum number of cells with transmission on all TAB connectors supporting an operating band, but its existence is not limited to that condition
- 型別：`tab_tx_min_cell_group: list<tab_connector_id>`，per operating band
- 說明：這是 1-H 傳導 TX 需求（功率、ACLR、unwanted emissions）套用的「群組」單位，宣告 ID 為 D.34。

### [1411-004] TAB connector RX min cell group
- 出處：TS 38.141-1 V19.5.0 §3.1, p.26
- 原文：
> TAB connector RX min cell group: operating band specific declared group of TAB connectors to which BS type 1-H conducted RX requirements are applied
>
>     NOTE: Within this definition, the group corresponds to the group of TAB connectors which are responsible for receiving a cell when the BS type 1-H setting corresponding to the declared minimum number of cells with reception on all TAB connectors supporting an operating band, but its existence is not limited to that condition
- 型別：同上，宣告 ID 為 D.33。

### [1411-005] active transmitter unit（TX 分支的定義）
- 出處：TS 38.141-1 V19.5.0 §3.1, p.24
- 原文：
> active transmitter unit: transmitter unit which is ON, and has the ability to send modulated data streams that are parallel and distinct to those sent from other transmitter units to a BS type 1-C antenna connector, or to one or more BS type 1-H TAB connectors at the transceiver array boundary
- 說明：這是 3GPP 對「TX 分支數」最接近的定義——能送出彼此獨立平行資料流的 transmitter unit。一個 transmitter unit 可對到一個或多個 TAB connector。

### [1411-006] single-band connector / multi-band connector
- 出處：TS 38.141-1 V19.5.0 §3.1, p.25（multi-band）、p.26（single-band）
- 原文：
> multi-band connector: antenna connector of the BS type 1-C or TAB connector of the BS type 1-H associated with a transmitter or receiver that is characterized by the ability to process two or more carriers in common active RF components simultaneously, where at least one carrier is configured at a different operating band than the other carrier(s) and where this different operating band is not a sub-band or superseding-band of another supported operating band
>
> single-band connector: antenna connector of the BS type 1-C or TAB connector of the BS type 1-H supporting operation either in a single operating band only, or in multiple operating bands but does not meet the conditions for a multi-band connector
- 型別：`connector.band_capability: enum {single-band, multi-band}`（宣告 ID D.8）

### [1411-007] 額定/最大輸出功率的參考點符號（§3.2）
- 出處：TS 38.141-1 V19.5.0 §3.2, p.28
- 原文：
> Pmax,c,AC             Maximum carrier output power measured per antenna connector
> Pmax,c,cell           The maximum carrier output power per TAB connector TX min cell group
> Pmax,c,TABC           The maximum carrier output power per TAB connector
> Prated,c,AC           The rated carrier output power per antenna connector
> Prated,c,sys          The sum of Prated,c,TABC for all TAB connectors for a single carrier
> Prated,c,TABC         The rated carrier output power per TAB connector
> Prated,t,AC           The rated total output power declared at the antenna connector
> Prated,t,TABC         The rated total output power declared at TAB connector
> PSBFD,max,c,TABC      The maximum carrier output power per TAB connector for SBFD operation of SBFD-capable BS
> PSBFD,rated,c,TABC    The rated carrier output power per TAB connector for SBFD operation of SBFD-capable BS
> PSBFD,rated,t,TABC    The rated total output power declared at TAB connector for SBFD operation of SBFD-capable BS
- 單位：dBm
- 說明：`Prated,c,sys = Σ Prated,c,TABC`（單一 carrier、全部 TAB connector 之和）是唯一把「per connector」加總成「系統級」的符號，模擬時可用它換算總 DL 功率。

### [1411-008] Ncells、NTXU,counted、NRXU,active 等計數符號（§3.2）
- 出處：TS 38.141-1 V19.5.0 §3.2, p.27–28
- 原文：
> Iuant                gNB internal logical interface between the implementation specific O&M function and the RET antennas and TMAs control unit function of the gNB
> Ncells               The declared number corresponding to the minimum number of cells that can be transmitted by an BS type 1-H in a particular operating band
> NRXU,active          The number of active receiver units. The same as the number of demodulation branches to which compliance is declared for chapter 8 performance requirements
> NRXU,counted         The number of active receiver units that are taken into account for conducted Rx spurious emission scaling, as calculated in clause 7.6.1
> NRXU,countedpercell  The number of active receiver units that are taken into account for conducted RX spurious emissions scaling per cell, as calculated in clause 7.6.1
> NTXU,counted         The number of active transmitter units as calculated in clause 6.1, that are taken into account for conducted TX output power limit in clause 6.2.1, and for unwanted TX emissions scaling
> NTXU,countedpercell  The number of active transmitter units that are taken into account for conducted TX emissions scaling per cell, as calculated in clause 6.1
- 型別：整數；`NRXU,active` = 解調分支數（RX 分支數）
- 說明：**這是 3GPP 對「RX 分支數」唯一有數值語意的定義**：NRXU,active 等於 §8 效能需求宣告的 demodulation branch 數。Iuant 的定義也在此（O&M ↔ RET/TMA 控制單元的 gNB 內部邏輯介面）。

### [1411-009] NTXU,counted 與 Ncells 的關係（§6.1.2）
- 出處：TS 38.141-1 V19.5.0 §6.1.2, p.91
- 原文：
> The manufacturer shall declare the minimum number of supported geographical cells (i.e. geographical areas). The minimum number of supported geographical cells (Ncells, D.24) relates to the BS setting with the minimum amount of cell splitting supported with transmission on all TAB connectors supporting the operating band. The manufacturer shall also declare TAB connector TX min cell groups (D.34). Every TAB connector supporting transmission in an operating band shall map to one TAB connector TX min cell group supporting the same operating band. The mapping of TAB connectors to cells is implementation dependent.
>
> The number of active transmitter units that are considered when calculating the emissions limit (NTXU, counted) for BS type 1-H is calculated as follows:
>
>     NTXU, counted = min(NTXU,active, 8·Ncells)
>
> Further:
>     NTXU,countedpercell = NTXU,counted/Ncells
>
>     NTXU,countedpercell is used for scaling the basic limits as described in clause 6.6.
>
>     NOTE: NTXU,active depends on the actual number of active transmitter units and is independent to the declaration of Ncells.
- 公式：`NTXU,counted = min(NTXU,active, 8 × Ncells)`；`NTXU,countedpercell = NTXU,counted / Ncells`
- 說明：每個支援傳送的 TAB connector **必須且只能**對映到一個同頻帶的 TX min cell group（多對一）。TAB→cell 的實際對映是 implementation dependent（與 38.104 [104-046] 一致）。

### [1411-010] NRXU,counted 與 RX min cell group（§7.6.1）
- 出處：TS 38.141-1 V19.5.0 §7.6.1, p.187
- 原文：
> For BS type 1-H manufacturer shall declare TAB connector RX min cell groups (D.33). Every TAB connector of BS type 1-H supporting reception in an operating band shall map to one TAB connector RX min cell group, where mapping of TAB connectors to cells/beams is implementation dependent.
>
> The number of active receiver units that are considered when calculating the conducted RX spurious emission limits (NRXU,counted) for BS type 1-H is calculated as follows:
>
>         NRXU,counted = min(NRXU,active , 8 × Ncells)
>
> NRXU,countedpercell is used for scaling of basic limits and is derived as NRXU,countedpercell = NRXU,counted / Ncells, where Ncells is defined in clause 6.1.
>
>     NOTE: NRXU,active is the number of actually active receiver units and is independent to the declaration of Ncells.
- 公式：`NRXU,counted = min(NRXU,active, 8 × Ncells)`
- 說明：RX 側與 TX 側完全對稱。注意原文這裡寫的是「TAB connectors to cells/**beams**」，TX 側（§6.1.2）只寫 cells。

### [1411-011] 1-H 傳導測試參考點（每個 TAB connector 各自測）
- 出處：TS 38.141-1 V19.5.0 §4.5.2.1 / §4.5.2.2, Figure 4.5.2.1-1 / 4.5.2.2-1, p.45–46
- 原文：
> Unless otherwise stated, the conducted transmitter characteristics in clause 6 are specified at the transceiver array boundary at the TAB connector(s) with a full complement of transceiver units for the configuration in normal operating conditions.
> […]
> Unless otherwise stated, for the tests in clause 6 of the present document, the requirement applies for each transmit TAB connector.
> […]
> For the tests in clause 7 of the present document, the requirement applies at each receive TAB connector.
>
> Conducted receive requirements are tested at the TAB connector, with the remaining receiver units(s) disabled or their TAB connector(s) being terminated.
- 說明：Figure 4.5.2.1-1／4.5.2.2-1 中 transceiver unit array 標為 #1…#K，量測時只接一個 TAB(n)，其餘接 Load。**K 就是 TAB connector 的數量，但規格沒有給 K 的宣告 ID**（見 [1411-020]）。

### [1411-012] 內建 Iuant BS modem 的測試設定
- 出處：TS 38.141-1 V19.5.0 §4.5.3, p.47
- 原文：
> Unless otherwise stated, for the tests in the present document, the integrated Iuant BS modem shall be switched OFF. Spurious emissions according to clauses 6.6.5 and 7.6 shall be measured only for frequencies above 20 MHz with the integrated Iuant BS modem switched ON.
- 數值：`f > 20 MHz`（modem ON 時的 spurious 量測起點）
- 說明：這是 38.141-1 裡唯一把 Iuant/RET 納入 RF 一致性測試的條文，連結到 TS 37.461 的 modem option（見 [37461-001]）。

### [37466-002] Tilt 的定義（電子 vs 機械）
- 出處：TS 37.466 V19.0.0 §3.1, p.7–8
- 原文：
> Tilt (also downtilt, tilt angle, beamtilt): The elevation angle between the direction orthogonal to the antenna element axis and the maximum of its main beam in the elevation plane. A positive electrical tilt angle means that the antenna beam is directed below the direction orthogonal to the antenna axis. An antenna has separate values for electrical and mechanical tilt. The mechanical tilt is fixed by the geometry of the installation. In this TS the tilt referred to is always the electrical tilt unless otherwise stated.
- 符號慣例：**正值 = 向下傾**（beam 指向天線軸正交方向的下方）
- 說明：與 38.141-2 宣告座標系的 θ（向下為正，[1412-004]）同號；與 38.901 的 zenith θ 相反（`θ_901 = 90° + tilt`）。電子 tilt 與機械 tilt 是**分開的兩個值**，機械 tilt 由安裝幾何固定（可透過 device data 欄位 0x26 讀寫，見 [37466-014]）。

### [37466-003] **Tilt value：值域／單位／解析度**
- 出處：TS 37.466 V19.0.0 §3.1, p.8
- 原文：
> Tilt value: A signed integer used in elementary procedures to define the electrical tilt setting of the antenna. The tilt value is 10 times the antenna electrical tilt angle in degrees.
- 數值/型別：
  - 線上編碼：**2 octets, signed integer（2 補數、little endian）** → `int16`
  - 換算：`tilt_value = round(tilt_deg × 10)`，即**解析度 0.1°**
  - 理論值域：`int16` = −32768..32767 → −3276.8°..3276.7°；**實際可用值域由裝置宣告的 device data 欄位 0x06 / 0x07（max / min supported electrical tilt）決定**（見 [37466-014]），規格本身**未給固定值域**
- 說明：這是 `antenna_spec_v2.md` §12.2 第 2 項「RET tilt 的值域與單位」的答案。編碼格式由 §4.4（[37466-005]）規定。

### [37466-004] Calibrate / Configuration data 的定義
- 出處：TS 37.466 V19.0.0 §3.1, p.7
- 原文：
> Calibrate: Exercise the antenna drive unit over its entire range of travel to ensure fault-free operation and synchronise the measured and actual beam tilt of the antenna.
>
> Configuration data: A stored table or function defining the relationship between the physical position of the drive and electrical beam tilt.
- 說明：configuration data 就是「驅動器物理位置 ↔ 電子 beam tilt」的對映表/函數，格式 vendor specific（[37466-011]）。

### [37466-005] Multi-antenna units / 整數表示 / TMA subunit 編號

### [37461-001] Iuant Layer 1：兩種選項與資料率
- 出處：TS 37.461 V19.0.0 §1, p.5；§4.1, p.6

>     - 38.4 kbps ± 3 %
>     - 115.2 kbps ± 3 %

### [37462-001] Iuant Layer 2：HDLC frame 長度、位址、window、時序
- 出處：TS 37.462 V19.0.0 §4.2, p.7–8；§4.3 / §4.4 / §4.5, p.8
- 原文：
> 4.2 Frame lengths
> HDLC frame lengths may vary between 4 and N octets.
> All secondary devices shall support an N of 78 octets. A secondary device may, after XID negotiation, support a larger N.
>
> 4.3 Default address
> After reset, a secondary device shall use the no-device address (0x00). While it has the no-device address, it may only respond to device scan and address assignment messages, but any broadcast messages shall be evaluated without response.
>
> 4.4 Window size
> All devices shall support a window size of 1. A device may, after XID negotiation, support any window size up to 7.
>
> 4.5 Message timing
> A minimum of 3 ms shall elapse between receiving and transmitting messages.
> A secondary device shall, after reception of a command with the P/F bit set, start transmitting a response within 10 ms from the time the final flag octet of that command frame was received.
> The transmission of the response shall be finalised within the time t= n*10*4/datarate where n is the number of octets in the response frame including all HDLC framing overhead. The maximum gap time between two consecutive octets shall not exceed the time t= 3*10/datarate. This corresponds to a 25% utilisation of the Data Link Layer.
> The data rate is specified in TS 37.461 [3].
- 數值/型別：frame 4..N octets，**N ≥ 78（強制）**；`no-device address = 0x00`；window size 強制支援 1、XID 後可到 7；`t_gap_min = 3 ms`、回應起始 `≤ 10 ms`、回應完成 `t = n×10×4 / datarate`
- 說明：`MaxDataReceiveLength` / `MaxDataTransmitLength` = `SecondaryPayload{Receive,Transmit}Length − 3 octets`（37.466 §3.1, p.7，引用 37.462 §4.8.1）。

### [37462-002] **Device types（RET 單/多天線、TMA 的裝置型別碼）**
- 出處：TS 37.462 V19.0.0 §4.7, Table 4.7.1, p.8–9
- 原文：
> 4.7 Device types
> Three device types are defined and identified by the assigned 1-octet unsigned integer code.
>
> Table 4.7.1: Device types and codes
> Device Type | 1-octet unsigned integer code
> Single-Antenna RET Device | 0x01
> Multi-Antenna RET Device | 0x11
> Tower mounted amplifier (TMA) | 0x02
- 數值/型別：`device_type: enum {0x01 = Single-Antenna RET, 0x11 = Multi-Antenna RET, 0x02 = TMA}`（1 octet unsigned）
- 說明：**這就是「device type」的完整定義**——只有三種。device type 決定適用 Table 6.3.2（單天線 RETAP）、6.3.3（多天線 RETAP）或 6.3.4（TMAAP）。

### [37462-003] AISG v2.0 的引用（vendor code）
- 出處：TS 37.462 V19.0.0 §3.1, p.6（Vendor code 定義）；§4.8.3, p.9（XID PI 0x06）
- 原文：
> Vendor code: A unique ASCII 2-character code assigned to each vendor in AISG v2.0 [4].
> […]
> PI 0x06 | Vendor code as given in AISG v2.0 [4]
> PV 0x58 0x59 | Unique assigned vendor code as given in AISG v2.0 [4]

### [37466-030] Iuant 協定層次與 O-RAN `ald-communication` 的關係
- 出處（3GPP 側）：TS 37.466 V19.0.0 §1, p.6；§5, p.9；TS 37.461 §4.1, p.6；TS 37.462 §4.7, p.8–9
- 出處（O-RAN 側）：`07_oran_mp_v21.md` §9 — [MP-140]、[MP-141]、[MP-142]、[MP-143]（**不重新抽 O-RAN**）
- 原文（37.466 §5）：
> RETAP and TMAAP requires an assured in-sequence delivery service from the signalling transport and notification if the assured in-sequence delivery service is no longer available.
> […] Layer 2 provides a full-duplex link for the transmission of RETAP and TMAAP messages.
- 層次對照（3GPP Iuant ↔ O-RAN）：

| 層 | 3GPP Iuant | 出處 | O-RAN 的對應 | 出處 |
|---|---|---|---|---|
| L7 應用 | RETAP / TMAAP（EP、ProcedureCode、Tilt value） | TS 37.466 §1/§6 | AISG 2.0 Application Part，由 NETCONF client 自行組 binary | [MP-140] |
| L2 資料鏈結 | HDLC（frame 4..N≥78、window 1..7、位址指派、XID） | TS 37.462 §4 | 同為 HDLC | [MP-140] |
| L1 | RS485 option 或 Modem option（9.6/38.4/115.2 kbps） | TS 37.461 §4.1 | O-RU ALD port（DC 供電 + 資料），`o-ran-ald-port` | [MP-142] |
| 管理面封裝 | 無（Iuant 是 gNB 內部介面） | TS 37.466 §1 | `rpc ald-communication { port-id, ald-req-msg (binary ≤1200) }` 透傳 | [MP-141] |

- 說明（對接結論）：
  1. O-RAN 的 `ald-communication` RPC **只做 L7 binary 透傳**，`ald-req-msg` 裡放的就是 TS 37.466 定義的 RETAP/TMAAP 訊息（ProcedureCode + 參數）。O-RU 不解讀內容，因此 **tilt 的語意、單位（0.1°）、值域（device data 0x06/0x07）、時限（SetTilt < 2 min、Calibrate < 4 min）全部由 TS 37.466 決定，不在 O-RAN YANG 裡**（[MP-141] 結論：O-RAN 無 RET tilt leaf）。
  2. `ald-req-msg` 的 binary 上限 1200 octets（[MP-141]）遠大於 HDLC 的 N ≥ 78（[37462-001]），所以一個 RPC 可承載完整 EP。
  3. O-RAN 的 `elevation-tilt-offset-angle`（[MP-049]，int16 −90..90 deg，granularity uint8 0..30 deg）是**數位 tilt**，單位為「度」且解析度由 granularity 宣告；TS 37.466 的 RET tilt 是**機電 tilt**，單位固定 0.1°。**兩者單位、解析度、值域、控制路徑都不同，不可混用**；MP §15.4.4 也明文區分（"without the need for operation of additional ALDs"）。
  4. `07_oran_mp_v21.md` §9 末的待查項「RET 電子下傾角的值域與單位：需查 AISG 2.0 / 3GPP TS 37.466」→ **已由 [37466-003] + [37466-014] 補齊**。
  5. Shared O-RU 情境下由 Shared O-RU Host 負責 ALD 操作與跨 operator 的 RET 協調（[MP-143]）。

- `R-L6-nn+4`：`SelfTest` 期間致動器移動不得超過總 tilt 行程的 **±5%**，完成後參數回復初值。出處 `37466-018`。
- `R-L6-nn+5`：`{SetTilt, Calibrate, SelfTest}` 為 TCP；TCP 執行中最多再並行 1 個 EP，且 `ClearActiveAlarms` / `SendConfigurationData` / 其他 TCP 為 disallowed（回 `Busy`）。出處 `37466-010`。（validator / 狀態機可直接實作）
- `R-L6-nn+6`：未 `Calibrate` → tilt 程序回 `NotCalibrated`；未 `SendConfigurationData` → 回 `NotConfigured`；超出 `[min,max]` → 回 `OutOfRange`。出處 `37466-012`、`37466-013`。
- `R-L6-nn+7`：alarm 通知需先 `AlarmSubscribe`；reset 會清掉所有 alarm state 與訂閱；`state_flag: 0 = cleared, 1 = raised`。出處 `37466-009`、`37466-017`。
- `R-L6-nn+8`：**RET 機電 tilt（0.1°，TS 37.466）與 O-RAN 數位 beam tilt offset（deg，int16 −90..90，[MP-049]）是兩套獨立參數，單位/解析度/控制路徑皆不同，schema 必須分開存放、不可互相換算取代**。出處 `37466-003`、`MP-049`、`MP-141`（MP §15.4.4 明文區分）。
- `R-L6-nn+9`：O-RAN 架構下 RET 控制經 `rpc ald-communication` 以 binary 透傳 RETAP 訊息（`ald-req-msg ≤ 1200 octets`），O-RU 不解讀內容 ⇒ tilt 的語意與限制全部來自 TS 37.466。出處 `37466-030`、`MP-140`、`MP-141`。
- `R-L6-nn+10`：Iuant 的 **Modem option（同軸共纜）只適用於 UTRA / E-UTRA BS 與 NR BS type 1-C**；1-H/1-O 需用 RS485 或 O-RU ALD port。出處 `37461-001`、`1411-012`、`MP-142`。
- `R-L6-nn+11`：測試/量測時內建 Iuant BS modem 預設關閉；modem ON 時 spurious 只量 **> 20 MHz**。出處 `1411-012`。
