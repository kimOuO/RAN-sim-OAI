# 38.901 §7.3.0 明確寫 BS antenna 使用 uniform rectangular panel array，並定義：

$$
\boxed{(M_g,N_g,M,N,P)}
$$

其中 \(M_g\) 是一 column 中的 panels 數、\(N_g\) 是一 row 中的 panels 數；panel 之間有 \(d_{g,H},d_{g,V}\)，panel 裡 elements 則有 \(d_H,d_V\)。\(N\) 是 panel 的 columns 數，而 \(M\) 是每 column 中相同 polarization 的 antenna elements 數。\(P=1\) 或 \(2\) 分別表示 single / dual polarization。([歐洲電信標準協會][2])

38.901 本身畫出的模型就是：

```text
            dg,H
       <------------>

     Panel       Panel
    ┌──────┐    ┌──────┐
    │ X X  │    │ X X  │
    │ X X  │    │ X X  │
    │ X X  │    │ X X  │
    └──────┘    └──────┘
       ↑
      dg,V

panel 內：

        dH
    X ----- X
    |       |
 dV |       |
    X ----- X
```

而且 Figure 7.3-1 正式名稱就是 **Cross-polarized panel array antenna model**。

單一 BS antenna element 的 reference radiation pattern 使用：

$$
\theta_{3dB}=65^\circ
$$

$$
\phi_{3dB}=65^\circ
$$

$$
SLA_V=30\text{ dB}
$$

$$
A_{\max}=30\text{ dB}
$$

以及：

$$
G_{E,\max}=8\text{ dBi}
$$

這些都是 Table 7.3-1 直接給出的數值。

# Polarization 也可以直接納入 Spec

38.901 §7.3.2 還進一步正式定義 polarization model。

對 Model-1，它使用 polarization slant angle \(\zeta\)。其中：

$$
\zeta=0^\circ
$$

代表 purely vertically polarized element，而：

$$
\zeta=\pm45^\circ
$$

代表一對 cross-polarized antenna elements。([歐洲電信標準協會][2])

所以如果完全照 38.901 描述，一個 antenna element 的物理模型其實可以包含：

```yaml
polarization:

  P: 2

  slant_angles:
    - +45 deg
    - -45 deg
```

這裡的 `+45/-45` 不是我自己指定的例子，而是 38.901 §7.3.2 明文使用的 cross-polarized pair。

# Layer 2：3GPP 能提供的 Spec 就只能到這裡

這部分特別重要。

38.104 **沒有**提供：

```yaml
64T64R:
  elements: 192
```

也沒有：

```yaml
trx_to_element:
  ...
```

這些都不是標準欄位。

38.104 §4.3.2 真正正式提供的是這個架構：

```text
      Transceiver Unit Array
              TRXUA
                │
                │
      Transceiver Array Boundary
                │
              TAB
                │
                ▼
      Radio Distribution Network
               RDN
                │
                ▼
          Antenna Array
               AA
                │
                ▼
 Radiated Interface Boundary
               RIB
```

而且規範非常明確：

```yaml
TRXUA:
  transmitter_units:
    number: implementation_specific

  receiver_units:
    number: implementation_specific
```

不是我們不知道，而是 **38.104 本身就寫 implementation specific**。([歐洲電信標準協會][3])

另外它明確說：

* TX unit 與 RX unit 可以組合成 transceiver unit。
* TX/RX units 可以處理 parallel independent modulated symbol streams。
* RDN 是 linear passive network。
* RDN 把 TRXUA RF power 分配到 antenna array。
* receive direction 則把 antenna-array signals 分配回 TRXUA。
* 這個 distribution 是 implementation specific。([歐洲電信標準協會][3])

所以 Layer 2 如果堅持「只寫標準資料」，**不應該再放任何固定 TRX 數量或 element mapping。**

# Layer 3 再加入 MIMO / Codebook 的正式 schema

除了 `CSI-RS-ResourceMapping`，38.331 還真的提供 `CodebookConfig` ASN.1。

所以 MIMO antenna-mode 部分可以繼續完全使用 3GPP 欄位，而不用自己發明 `mimo_mode`。

核心可以整理為：

                    two-one:
                      restriction_size: 8

                      restriction_size: 64

                      restriction_size: 16

                    three-two:
                      restriction_size: 96

                    six-one:
                      restriction_size: 24

                    four-two:
                      restriction_size: 128

                    eight-one:
                      restriction_size: 32

                    four-three:
                      restriction_size: 192

                    six-two:
                      restriction_size: 192

                    twelve-one:
                      restriction_size: 48

                    four-four:
                      restriction_size: 256

                    eight-two:
                      restriction_size: 256

                    sixteen-one:
                      restriction_size: 64

          typeI-SinglePanel-ri-Restriction:
            type: BIT_STRING
            size: 8


        typeI-MultiPanel:

          ng-n1-n2:

            allowed_configurations:

              two-two-one:
                restriction_size: 8

              two-four-one:
                restriction_size: 16

              four-two-one:
                restriction_size: 8

              two-two-two:
                restriction_size: 64

              two-eight-one:
                restriction_size: 32

                restriction_size: 16

              four-two-two:

          ri-Restriction:

    type2:

          typeII-RI-Restriction:

這些名稱不是重新命名過的名稱，而是 `CodebookConfig` ASN.1 裡面的正式欄位。([歐洲電信標準協會][1])

尤其這裡可以看到一件很重要的事情：

```text
typeI-SinglePanel
typeI-MultiPanel
```

是 **logical codebook configuration**。

它不是直接指 38.901 的 physical panel。

也就是：

```text
38.901
Mg / Ng / M / N / P
        ↓
physical antenna geometry


38.331
typeI-SinglePanel
typeI-MultiPanel
n1-n2
ng-n1-n2
        ↓
codebook / logical antenna ports
```

名稱很像，但標準沒有說兩者必須直接一對一。

# Beamforming 如果只使用 3GPP 文件，可以描述到哪？

這邊我也把之前自訂的：

```text
architecture: digital
architecture: analog
architecture: hybrid

W_RF
W_BB
```

全部移除。

因為這些雖然是學術與工程上非常常用的模型，**但不是我們目前這幾份 3GPP 文件中那個統一 AntennaConfig 的正式欄位。**

如果只使用這些 3GPP 文件，最直接的 beamforming parameter 是 38.901 §7.3.1 的 antenna port mapping。

它對 legacy BS uniform linear array 定義：

$$
\boxed{
w_m=
\frac{1}{\sqrt{M}}
\exp
\left[
-j
\frac{2\pi}{\lambda}
(m-1)d_V
\cos\theta_{\mathrm{etilt}}
\right]
}
$$

其中：

```yaml
beam_tilt:

  m:
    range: 1..M

  M:
    meaning: number of array elements

  lambda:
    meaning: wavelength

  d_V:
    meaning: vertical element spacing

  theta_etilt:
    range: 0..180 deg

    perpendicular_to_array:
      value: 90 deg

  w_m:
    type: complex_weight
```

38.901 明確說這些 fixed phase shifts / complex weights 用來取得 vertical beamtilt。([歐洲電信標準協會][2])

所以這個才是目前可以直接放進「純 3GPP-derived beamforming schema」裡的東西。

# MIMO 的「mode」則主要由 port + codebook + RI / PMI 表達

3GPP 並沒有一個：

```yaml
mimo_mode:
  rank: 4
  beam: ...
```

這種統一 IE。

它是由數個標準欄位共同決定。

例如 CSI-RS resource 先有：

```yaml
nrofPorts: p32
```

然後 `CodebookConfig` 決定 codebook family、antenna-port arrangement/restriction，再透過 RI / PMI reporting 表達 rank 與 precoding selection。

38.214 Release 19 還明確允許用 `portSubsetIndicator` 指定 antenna-port subset；bitmap 最長 32 bits，bit \(p_i\) 對應 antenna port \(3000+i\)，而 bit value 0 表示對應的 antenna port disabled。([歐洲電信標準協會][4])

因此如果只保留 3GPP 欄位：

```yaml
logical_antenna_mode:

  CSI-RS-ResourceMapping:

    nrofPorts:
      allowed:
        - p1
        - p2
        - p4
        - p8
        - p12
        - p16
        - p24
        - p32


  CodebookConfig:

    codebookType:
      allowed_families:
        - typeI-SinglePanel
        - typeI-MultiPanel
        - typeII
        - typeII-PortSelection

    RI_restriction:
      present_in_CodebookConfig: true

    codebook_subset_restriction:
      present_in_CodebookConfig: true


  portSubsetIndicator:

    maximum_length:
      value: 32 bits

    port_numbering:
      expression: 3000 + i

    bit_0:
      meaning: corresponding antenna port disabled
```

這就已經完全是標準中存在的資訊。

# 因此真正「純 3GPP」的三層關係

最後可以濃縮成這張：

```text
┌──────────────────────────────────────────────┐
│ TR 38.901 §7.3                              │
│ Physical / channel-model antenna            │
│                                              │
│ (Mg, Ng, M, N, P)                           │
│ dg,H / dg,V                                 │
│ dH / dV                                     │
│ P = 1 / 2                                   │
│ θ3dB / φ3dB                                 │
│ SLA_V / Amax / GE,max                       │
│ polarization slant ζ                        │
│                                              │
│ antenna-port mapping: wm                    │
└───────────────────┬──────────────────────────┘
                    │
                    │ mapping not standardized
                    │ as a universal table
                    ▼
┌──────────────────────────────────────────────┐
│ TS 38.104 §4.3.2                            │
│ RF architecture                             │
│                                              │
│ TRXUA                                       │
│   transmitter units = implementation-spec.  │
│   receiver units    = implementation-spec.  │
│                                              │
│ TAB                                         │
│ ↓                                           │
│ RDN = linear passive network                │
│       distribution implementation-specific  │
│ ↓                                           │
│ Antenna Array                               │
│ ↓                                           │
│ RIB                                         │
└───────────────────┬──────────────────────────┘
                    │
                    │ no universal
                    │ element↔TRX↔port table
                    ▼
┌──────────────────────────────────────────────┐
│ TS 38.331 / TS 38.214                       │
│ Logical antenna / MIMO                      │
│                                              │
│ CSI-RS-ResourceMapping                      │
│   nrofPorts =                               │
│   {1,2,4,8,12,16,24,32}                    │
│                                              │
│ CodebookConfig                              │
│   Type-I SinglePanel                        │
│   Type-I MultiPanel                         │
│   Type-II                                   │
│                                              │
│ n1-n2 / ng-n1-n2                            │
│ RI restriction                              │
│ codebook subset restriction                 │
│ portSubsetIndicator                         │
│ PMI / RI                                    │
└──────────────────────────────────────────────┘
```

所以你原本想找的：

```text
192 elements
    ↓
64 TRX
    ↓
32 antenna ports
    ↓
4 layers
```

**不能寫成 3GPP 標準 schema rule。**

38.901 可以告訴你 physical geometry；38.104 明文說 TRX 數量以及 RDN distribution 是 implementation-specific；38.331/38.214 則獨立定義 logical antenna ports 與 MIMO codebook。這幾份規範之間沒有定義一張通用的 `physical elements → TRX → CSI-RS ports` 對照表。([歐洲電信標準協會][2])
