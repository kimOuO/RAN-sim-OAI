# ANR 情境測驗 v10 —— 現況落差與改動計畫

> 對照:`docs/ANR情境測驗_v10.docx`(2026-08-25)+ `docs/觀測資料參數.pdf`
> 現況基準:本 repo 的 E2SM-ANR(ran_func 6)實作與十二題劇本(對 v8 版完成)
> 撰寫日期:2026-08-25

---

## 0. 結論

v10 **不是修訂,是改版**。落差分三層,由重到輕:

| 層 | 內容 | 影響 |
|---|---|---|
| **A 行為** | **四題的正解變了**(5 / 6 / 7 / 12) | 劇本與 guard 都要改;現有驗證結論部分失效 |
| **B 結構** | 觀測資料的**容器與鍵名全面重組**,每個指標改帶 baseline 與趨勢 | RIC 現行 xApp 讀不到資料 |
| **C 欄位** | 新增約 12 個欄位/容器,並要求**移除**旗標欄位 | sim 側新增量測 |

其中 **A 與 C 的「移除旗標」互為因果**:v10 明訂旗標狀態非 E2 可觀測,
xApp 必須由**行為訊號**推論封鎖存在 —— 這是第 12 題的核心考點,
而我們現在把 `flags` 直接放在 indication 裡,等於把答案送給 xApp。

---

## A. 行為變更 —— 四題的正解改了

| 題 | 分類(v10) | 我們照 v8 做的 | v10 要求 | 差異性質 |
|---|---|---|---|---|
| **5** | 二 PCI 混淆 | **擋**:抑制 ADD、零 E2 動作 | **主動**:`RC_MOBILITY_HO_CONTROL` 逐 UE 以 CGI 下達換手(繞過 PCI 歧義)+ `SMO_NOTIFY` 請管理面補建關係與 PCI 重配 | 由「不動手」變「動手」 |
| **6** | 七 Xn 連線管理 | **不動手**:只發 SMO_NOTIFY | **set `xnBlocklist`** 禁用換手路徑(不拆線),Xn 恢復後 `clear` | 由「不動手」變「動手」 |
| **7** | 五 過射/劣質 | set `hoBlocklist` | **`hoBlocklist` + `noRemove` 成對**(TS 28.313 §6.4.1.3.5 Step 2 為複合動作);解除時兩者都 clear | 動作不完整 |
| **12** | 六 封鎖與白名單管理 | **不動手**:只稽核 + SMO_NOTIFY | **修復**:對無依據之封鎖 `clear hoBlocklist / xnBlocklist`;有失敗史的正當封鎖(對照組)不得碰 | 由「不動手」變「修復」 |

> v10 的「不動手」題只剩下**管理面職權**事項(PCI 重配、Xn 連線建立、保護條目)——
> 那些一律走 `SMO_NOTIFY`。過去我們把 6 / 12 歸為零動作,在 v10 是**漏做**。

**第 11 題另有實質變更**:回收判準由「年齡大 + 換手嘗試 0」改為
**雙歸零 aging** —— 量測樣本速率與換手嘗試速率**同步**歸零並持續 6 小時。
理由是防誤刪暫時靜默者。另需 PLMN 檢核(非本網只通報不建)與
CCC 組態變更事件佐證(新 `O-NRCellCU` 實例 = 新 cell 誕生)。

## B. 觀測資料結構變更

### B.1 每個指標都變成物件

```jsonc
// v10
"RLF.DetectedRate.NCGI-S02": {
  "currentPerMin": 3.4,
  "baselinePerMin": 0.2,                        // ← 歷史統計參照
  "trendLast30Min": [0.3,1.0,2.2,3.0,3.4,3.4]   // ← 六窗趨勢
}

// 現況
"rlfKpm": { "cellLevel": { "s02_c0": { "RLF.DetectedRate": 3.4 } } }
```

三件事同時變:**鍵名扁平化為 `指標.NCGI`**、**值變成物件**、
**多了 baseline 與 trendLast30Min**。

`baseline` 是 v10 的判準骨幹 —— 幾乎每題都靠「相對 baseline 的變化」定調,
不是絕對值。這需要 sim 端保存歷史統計,目前完全沒有。

### B.2 容器合併

| v10 位置 | 我們現在的位置 |
|---|---|
| `kpmIndication.cellLevel.RLF.*` | `rlfKpm.cellLevel` |
| `kpmIndication.cellLevel.HO.IntraSys.*` | `mroKpm.cellLevel` |
| `kpmIndication.cellLevel.RRC.ConnReEstabInboundRatePerMin` | `rlfKpm.cellLevel` |
| `e2MessageCopyAggregate.reestablishmentInboundByPreviousPci[]` | `rlfKpm.reestablishmentInboundByPreviousPci[]` |
| `cgiResolutionSampling[]`(indication 內的容器) | 只有 `cgi_resolve` 這支查詢端點 |

`rlfKpm` / `mroKpm` 這兩個頂層容器在 v10 **不存在**。

## C. 欄位逐項對照

### C.1 缺少(需新增)

| 欄位 | 容器 | 備註 |
|---|---|---|
| `DRB.UEThpDl` / `DRB.UEThpUl` | cellLevel | TS 28.552 §5.1.1.3;func5 有、func6 沒有 |
| `DRB.PdcpSduVolumeDL` / `UL` | cellLevel | §5.1.2.1 |
| `DRB.RlcSduDelayDl` | cellLevel | §5.1.3.3 |
| `MM.HoPrepInterFailRatePerMin{cause}` | perNeighbourRelation | **準備**階段失敗,cause 用 38.423 §9.2.3.2 |
| `MM.HoExeInterFailRatePerMin{子計數}` | perNeighbourRelation | **執行**階段失敗,含 `RrcReestabReq` |
| `MM.HoFailCumulativeSinceCreation` | perNeighbourRelation | 準備+執行合計(我們的是 cause 分列) |
| `HO.IntraSys.ToWrongCellRate` | **perNeighbourRelation** | 目前只有 cell 級 |
| `trendLast30Min_*` | perNeighbourRelation / measAggregate | 六窗序列 |
| `previousArfcn` | reestablishmentInbound | 只有 PCI 不足以消歧 |
| `plmnIdentity` | cgiResolutionSampling | 第 11 題的本網檢核靠它 |
| `granularityPeriod` | 頂層 | 速率語意的定義域 |
| `cccConfigurationEvents[]` | 新容器 | E2SM-CCC 組態變更;第 11 題佐證 |
| 全部 `baseline*` | 所有指標 | 見 B.1 |

**現有 `handoverFailureCauseRatePerMin` 要拆成準備/執行兩支** ——
v10 靠這個區分「換手發不出去」與「換過去失敗」,是第 6 題與第 7 題的鑑別點。

### C.2 多餘(需移除)

| 欄位 | 為什麼要拿掉 |
|---|---|
| `flags{hoBlocklist,noRemove,xnBlocklist}` | **v10 明訂旗標狀態非 E2 可觀測** |
| `isHoAllowed` / `isRemoveAllowed` / `isXnAllowed` | 同上;屬管理面屬性,9.3.38 無此欄位 |
| `relationAgeSec` | v10 的 aging 判準是**使用量雙歸零**,不是年齡 |

第 12 題的整個考點就是「**在讀不到旗標的前提下,由四項行為訊號推論出被封鎖**」:
量測極強且持續 + 換手嘗試恆為 0 + `hoValidated=false` + 建立以來失敗累計為空。
我們現在直接把 `flags.hoBlocklist=true` 送出去,這題就不成題。

## D. sim 能力缺口

| # | 缺口 | 影響 | 現況 |
|---|---|---|---|
| D1 | **`xnBlocklist` 完全沒有生效** | 第 6 題 v10 做不出來 | 欄位存在、可設,但換手路徑不看它(`hoBlocklist` 有生效,在 A3 評估) |

| D6 | 無 CCC 組態變更事件流 | 第 11 題組態面佐證 | CCC 只做 cell 開關 |

## E. 分階段計畫

### P0 — 行為對齊(不做就有題目不成題)

| 項 | 工作 | 檔案 |
|---|---|---|
| P0-1 | `xnBlocklist` 生效:A3 與 handover_executor 跳過該關係,失敗原因回 `TXnRELOCprepExpiry` | `a3_handover_calculation.py`、`handover_executor.py` |
| P0-2 | **indication 移除 `flags` / `isXxxAllowed` / `relationAgeSec`** | `anr_query_actor.py::_relation_to_ie` |
| P0-3 | `cgi_resolve` 補 `plmnIdentity`,並在 indication 內提供 `cgiResolutionSampling[]` 容器 | `anr_kpm.py`、`anr_query_actor.py` |
| P0-4 | 劇本改版:Q5(改為需要 RC HO control)、Q6(改為需要 set xnBlocklist)、Q7(成對旗標)、Q12(需要可修復的無依據封鎖 + 有失敗史的對照組) | `docs/scenarios/anr_*.json`、`scripts/anr_arm.py` |

> **P0-2 要先跟 RIC 談**:拿掉 `flags` 會讓他們現行 guard 的確認邏輯失效。
> v10 的替代機制是 `confirm(cellId, expect)` 的 **BEHAVIOR 期望值** ——
> 以行為訊號確認旗標生效,而不是讀旗標。這是雙邊都要改的介面變更。

### P1 — 資料模型對齊(RIC 讀得到才有意義)

| 項 | 工作 | 難度 |
|---|---|---|
| P1-1 | 指標值改物件 `{current*, baseline*, trendLast30Min[]}` | 中 —— 需要歷史統計儲存 |
| P1-2 | 鍵名扁平化 `指標.NCGI`;`rlfKpm`/`mroKpm` 併入 `kpmIndication.cellLevel` | 低(純重組) |
| P1-3 | 補 5 個 cell 級 KPI(UEThpDl/Ul、PdcpSduVolumeDL/UL、RlcSduDelayDl)—— func5 已有,搬到 func6 | 低 |
| P1-4 | `perNeighbourRelation` 失敗率拆準備/執行兩支 + per-relation `ToWrongCellRate` + `HoFailCumulativeSinceCreation` | 中 |
| P1-5 | 六窗趨勢序列(30 分鐘 / 5 分鐘一窗) | 中 —— 與 P1-1 共用歷史層 |

**相容策略**:P1 是破壞性變更。建議 **`ANR_SCHEMA=v8|v10` 環境變數並行**,
adapter 依訂閱參數決定送哪版,讓 RIC 端可以分批遷移 —— 否則切換當天兩邊都動不了。

### P2 — 補完

## F. 對既有驗證結論的影響

| 題 | v8 驗證結論 | v10 下是否仍成立 |
|---|---|---|
| 1 / 2 / 3 / 4 / 8 / 9 / 10 | 通過 | ✅ 判準未變,僅資料格式要改 |
| 11 | 通過 | ⚠️ **判準改了**(雙歸零 + PLMN + CCC 佐證),需重驗 |
| 5 / 6 / 7 / 12 | 通過 | ❌ **正解變了**,原結論不適用,需重做 |

> 也就是說:**十二題裡有四題要重做、一題要重驗**,七題只需跟著改資料格式。

## G. 建議順序

1. **先跟 RIC 對齊 P0-2**(移除旗標)—— 這是雙邊介面變更,越早談越好
2. **P0 全做完**,四題重做 + 十一題重驗 —— 讓「行為」先對齊 v10
3. **P1 用雙版本並行**上線,給 RIC 遷移窗口
4. **P2 補完**,然後跑一次完整的十二題 + 共存煙霧測試

P0 約 2–3 天,P1 約 1 週(歷史統計層是主要成本),P2 約 2–3 天。
