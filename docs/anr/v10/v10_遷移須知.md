# E2SM-ANR 觀測資料 v10 —— 給 RIC 端的遷移須知

> 範例輸出:[`samples/anr_indication_v10_sample.json`](samples/anr_indication_v10_sample.json)
> 切換方式:sim 端 `ANR_SCHEMA=v10`(**目前尚未切,預設仍為 v8**)
> 依據:`ANR情境測驗_v10.docx` 肆章

## 這不是加欄位,是重組 —— 現行 guard 會讀不到資料

四件事同時變:

| # | 變更 | 影響 |
|---|---|---|
| 1 | **鍵名扁平化** `指標.NCGI` | `cellLevel["s02_c0"]["RLF.DetectedRate"]` → `cellLevel["RLF.DetectedRate.s02_c0"]` |
| 2 | **值變成物件** | `3.4` → `{"currentPerMin":3.4,"baselinePerMin":0.2,"trendLast30Min":[...]}` |
| 3 | **容器合併** | `rlfKpm` / `mroKpm` **不存在** → 全部併入 `kpmIndication.cellLevel` |
| 4 | **移除旗標** | `flags` / `isHoAllowed` / `isRemoveAllowed` / `isXnAllowed` / `relationAgeSec` **不再送** |

### 單位字尾隨指標變

`current` / `baseline` 後面接的字尾不是固定的:

| 指標 | 字尾 |
|---|---|
| `RRU.PrbTot*` | `Pct` |
| `DRB.UEThp*` | `Mbps` |
| `DRB.PdcpSduVolume*` | `Mbit` |
| `DRB.RlcSduDelayDl` | `Ms` |
| 其餘速率類 | `PerMin` |

## ⚠️ 最需要注意的一項:旗標不再可觀測

v10 明訂**旗標狀態非 E2 可觀測**,所以:

1. **`confirm()` 不能再讀旗標判定生效** —— 改用行為訊號(`BEHAVIOR` 期望值),
   或訂閱下面的 `RC_E2NODEINFO_SUBSCRIBE` 等變更推播。
2. **第 12 題的考點就建立在這件事上** —— 要在讀不到旗標的前提下,
   由四項行為訊號推論出「這條關係被擋在換手準備之前」:
   目標量測極強且持續 + 該關係換手嘗試恆為 0 + `hoValidated=false` +
   `MM.HoFailCumulativeSinceCreation` 為 0。
   我們先前把 `flags` 直接送出去,等於把答案給你們 —— 那題形同白送。

## 新增可用的訂閱:`RC_E2NODEINFO_SUBSCRIBE`(已上線)

E2SM-ANR(ran_func **6**)的 SUB_REQ,**`action_id = 2`**:

- 只在 **NRT 變更時**才推,沒變就完全不送
- 內容:完整 `neighbourCellRelations` + `changeMarks{added, removed, versionBumped}`
- 對應 Event Trigger Style 3 / Change ID 2 + REPORT Style 3
- v10 指定它為 **`confirm()` 確認慣用式的載體**

`action_id` 0 / 1 維持原本的週期性 indication。**兩者可以同時訂** ——
一條看指標、一條等確認。

## 失敗率拆成兩支:第 6 題與第 7 題的鑑別點

`perNeighbourRelation` 原本的 `handoverFailureCauseRatePerMin` 已拆開:

| 欄位 | cause | 意義 | 對應題 |
|---|---|---|---|
| `MM.HoPrepInterFailRatePerMin` | `TXnRELOCprepExpiry`、`CellNotAvailable` | 連 Handover Request 都沒送成 | **第 6 題**(Xn 不通) |
| `MM.HoExeInterFailRatePerMin` | `RandomAccessProblem`、`RrcReestabReq` | 送出去了但 UE 接不進去 | **第 7 題**(過射/劣質) |

兩題外觀都是「換手失敗」,只有這一刀分得開。

## sim 端一併變更的行為(與資料格式無關,已生效)

| 項目 | 說明 |
|---|---|
| **`xnBlocklist` 現在真的會擋換手** | 先前欄位存在但換手路徑不看它,設了等於沒設。現在 A3 與 RC 直接下令都會擋,失敗原因回 `TXnRELOCprepExpiry`。**這是沉默的行為變更,請留意** |
| `plmnIdentity` | `cgi_resolve` 已回傳,第 11 題的本網檢核可用 |
| `previousArfcn` | `reestablishmentInboundByPreviousPci` 已含,PCI 消歧用 |

## 四題的正解變了(需重做 guard)

| 題 | v8 | v10 |
|---|---|---|
| 5 PCI 混淆 | 擋(零動作) | **`RC_MOBILITY_HO_CONTROL` 以 CGI 逐 UE 換手** + SMO_NOTIFY |
| 6 Xn | 不動手 | **set `xnBlocklist`**,Xn 修好後 clear |
| 7 有害鄰居 | `hoBlocklist` | **`hoBlocklist` + `noRemove` 成對** |
| 12 稽核 | 不動手 | **修復無依據封鎖**;有失敗史的正當封鎖不得碰 |

第 11 題判準也改為**雙歸零**(`measSampleRatePerMin` 與 `MM.HoExeAttRatePerMin`
同步為 0 並持續),`relationAgeSec` 已移除。

## 建議的切換流程

1. 你們拿範例 JSON 評估改動量
2. 改完 guard、在本地對範例驗過
3. **通知我們**,我們才切 `ANR_SCHEMA=v10`
4. 切換後跑一次共存煙霧測試(十二支 guard × 中性健康場景)

切換是**全有全無**的 —— sim 端同一時間只送一種格式。
