## 四、功耗模型（`PEE.AvgPower` / `PEE.Energy`）

已由我方實作，貴方直接從 ran_func 5 取用，不需自行估算。

**模型**（ETSI ES 203 228 / EARTH 線性功耗模型）：

```
運作中：P_in = N_TRX × (P_static + Δp × P_out_max × load)
節能關站：P_in = N_TRX × P_sleep
```

| 符號 | 取值 | 來源 |
|---|---|---|
| `P_out_max` | 由該 cell 發射功率換算（dBm → W） | 場景設定，逐 cell，經 F1 帶到 CU |
| `load` | 累計已用 PRB ÷ 同期間 PRB 容量 | DU 累計器（開機以來），與分母同基準 |
| `N_TRX` | 預設 1 | env `PEE_N_TRX` |
| `P_static` | 預設 6.8 W | env `PEE_STATIC_W` |
| `Δp` | 預設 4.0 | env `PEE_SLOPE` |
| `P_sleep` | 預設 4.3 W | env `PEE_SLEEP_W` |

常數預設取 pico / small-cell 級別。若貴方情境需要 macro 級基站的量級，
四個常數皆可用環境變數覆寫，**不需改碼、不影響欄位名**。

**兩點請注意**：

1. 低功率場域中靜態功耗占絕對主導。走廊場景三顆 cell 為 10/10/5 dBm，
   輻射功率僅 0.01 W 量級，因此 `AvgPower` 在 6.80～6.81 W 之間變動。
   **這是正確的物理結果**，不是欄位失效；要看到明顯的負載相關變化，
   需把 `PEE_SLOPE` / 發射功率調到 macro 量級。
2. `PEE.Energy` 給的是**自該 cell 出現以來的累計值**（kWh），關站期間按
   `P_sleep` 計。取任意區間耗能請做差分；反之（由區間值還原累計）不可行，
   故採累計。

### `cellAvailablePer` 的定義

「不可用」在我方模型中等同**節能關站**（`is_active=False`）：該 cell 不參與
排程，tick 不累加，與存在期間經過的 tick 數之差即為中斷時間。分母自該 cell
第一次出現起算，因此新加入的 cell 不會被歷史拖累。

實測：將 `e03:mid` 設為 `is_active=False` 後，其 `cellAvailablePer` 由 99.9%
逐步降至 48.6%，同時 `e03:src` / `e03:nbr` 維持 99.9%。

## 七、`servedNrCells: 0` 的根因與修正

**根因**：E2AP §9.2.26 規定 `e2nodeComponentRequestPart` 裝的是該介面**自身
setup 訊息的原文**；F1 介面即 F1AP F1 SETUP REQUEST 的 APER bytes。我方先前
在此放的是自訂 TLV，貴方照 F1AP 解析自然解不到 `Served-Cells-List`，
R-NIB 因而顯示 `servedNrCells: 0`。

**修正**：改送真正的 F1AP F1SetupRequest（TS 38.473 §9.2.1.4）：

| IE | id | 內容 |
|---|---|---|
| TransactionID | 78 | 0 |
| gNB-DU-ID | 42 | DU 編號 |
| gNB-DU-Name | 45 | DU 名稱（已濾除 PrintableString 不允許的字元） |
| gNB-DU-Served-Cells-List | 44 | 每 cell 一筆 Served-Cell-Information |
| RRC-Version | 171 | latest |

每筆 `Served-Cell-Information` 含 `nRCGI`（PLMN + 36-bit NR Cell Identity）、
`nRPCI`、`fiveGS-TAC`、`servedPLMNs`、`nR-Mode-Info`（TDD：`nRARFCN` +
band n78 + SCS 30 kHz + PRB 數）。

**NR-CGI 與 KPM 一致**：F1AP 裡的 NCI 走與 KPM indication 完全相同的
explicit-first / SHA-1 fallback，兩邊必然對得起來。多 gNB 場景的 cell 都有明確 NCI（第八節），
SHA-1 只剩舊共用節點 e00 在用。

實測解碼結果（走廊場景）：

```
servedNrCells = 3
  pci=0  nci=23283524961  arfcn=633333
  pci=1  nci=24424728277  arfcn=633333
  pci=2  nci=58935151703  arfcn=633333
```

`measurementTimingConfiguration` 為必填但內容我方無真實廣播排程，送空字串。

## 八、多 gNB（2026-09-27 起）

依據 `docs/architecture/multi_gnb_plan.md`；與 RIC 聯測驗收 7–18 全數通過。

### 8-1　E2 node 與識別

| 項目 | 規則 | 例（走廊，區塊 2） |
|---|---|---|
| E2 node | **每個 gNB 一個**（一個 CU、一條 SCTP、一次 E2 Setup） | src / nbr / mid 三個 node |
| gNB ID | `0xe00 \| (16 × 區塊 + e2_index)`，22 bit | nbr = `0x000e21` |
| meid / ranName | `gnb_<MCC>_<MNC 3 位>_<gNB ID 6 位 hex>` | `gnb_208_095_000e21` |
| NCI | `gNB ID << 14 \| local_cell_id`（36 bit，TS 38.300 §8.2） | `59260928` = `0x003884000` |
| ncgi 字串（`ncgiStd`） | `<PLMN 6 位>-<NCI 9 位 hex>` | `208095-003884000` |
| cell 名 | `<gNB ID 後三位>:<registry 名>` | `e21:nbr` |

- 每個 node 的 E2 Setup **只含自己的 cell**（F1AP servedNrCells 只列本 gNB 的 DU 所服務的 cell）。
- 這些值在啟動前就由 DT I-1 / I-2 的 `e2_identities[]` 公布，與執行期相同。
- 舊共用節點 `gnb_208_095_000e00` 不變（cell 沒有明確 NCI，仍用 SHA-1），保留給 RIC 常駐 xApp。

### 8-2　ran_func 5（FULLKPM）

| 欄位 | 多 gNB 語意 |
|---|---|
| `e2[].cells[].cell_id`、`pm.<gnb>[].cell_id` | **cell 名**（`e21:nbr`），與 ran_func 6 的 `ncgi` 一致。2026-09-27 以前曾誤印成 15 位 NCI hex，已修 |
| `e2[].cells[].nci` / `ncgiStd`、`pm[].nci` / `ncgiStd` | 新增：數值 NCI 與 ncgi 字串（舊場景沒有明確 NCI 時不附） |
| `e2[].cells[].ues[]`、`ue_status[]` | **只列當下由本 node 服務的 UE**；`serving_gnb` 是 gNB 名稱。同一 UE 換到別的 gNB 後出現在那個 node 的報告 |
| `ues[].neighbors[]` | 鄰區可以是別的 gNB 的 cell（以 PCI@ARFCN 識別；gNB 的 NRT 能唯一解出時附 ncgi） |
| `ue_status[].ngap_id` | AMF UE NGAP ID，**跨 gNB 不變**（= ran_func 2 的 amf-UE-NGAP-ID、RC 的 UEID） |

ran_func 2（KPM）逐 cell indication 的 header `senderName` = `<cell 名>/0x<NCI 10 位 hex>`，NCI 與 E2 Setup 相同。

### 8-3　ran_func 6（ANR）

- `servingCells[].ncgi`、關係的 `targetCgi`、量測彙整的 cell 維持 **cell 名**（RIC 決定 A）；另附 `nci` / `ncgiStd`、`targetNci` / `targetNcgiStd`、`reportedNci` / `reportedNcgiStd`。
- 關係表可以有跨 gNB 的目標（來自 Xn Setup 交換的 served cells）；`xnX2Established` 表示兩個 gNB 之間 Xn 已建立。
- 反向關係（B→A）由對方 gNB 經 Xn 自建，出現在**對方 node** 的報告。

### 8-4　控制（RC / ANR / CCC）

| 項目 | 多 gNB 語意 |
|---|---|
| RC 3-1 目標 | `target_nci` 可以是別的 gNB 的 cell → 跨 gNB 換手（Xn；Xn 不通時依設定走 NG 或回 `TXnRELOCprepExpiry`）。回覆的 `target_nr_cell_id` 為目標 cell 的真實 NCI |
| RC 3-1 換手沒成 | 回 **RICcontrolFailure**（cause ricRequest/unspecified），RICcontrolOutcome（IE 32）帶 `{"result":"HANDOVER_FAILED","failureCause":…}`（2026-09-28 起；以前回 ACK） |
| RC 3-1-group | `target_pci`（+`target_arfcn`）可以是鄰 gNB 的 cell；匹配依 UE 量測中的鄰區 |
