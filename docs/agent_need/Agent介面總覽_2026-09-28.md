# Agent 介面總覽(2026-09-28,多 gNB 版)

取代 `Agent介面總覽_2026-09-23.md`。差別集中在:**一個場域有幾個 gNB 就有幾個 E2 node**,cell 識別改成 3GPP 規則(gNB ID ‖ 本地 cell ID),事件與稽核都標出發生在哪個 node。
依據:`docs/architecture/multi_gnb_plan.md`;與 RIC 聯測驗收 7–18 全數通過(2026-09-27,run 4–7 與並行場)。

Base URL:`http://<orchestrator>:8302/api/v0.1/Run_orchestrator/Agent_api/`,全部 **POST + JSON body**。
回應一律 `{"success": bool, "message": str, "data": {...}}`;錯誤時 `success=false`,`errors` 帶細節。
所有時間:`offset_s` = 自劇本起點的**劇本秒**(不是牆鐘);`ts_iso` 是對映出的牆鐘 UTC。

| 介面 | 端點 | 用途 | 能改什麼 |
|---|---|---|---|
| I-1 | `FieldReader/list` | 有哪些場域可跑,**每個 gNB 的 E2 識別** | 只讀 |
| I-2 | `FieldReader/config` | 一個場域的完整靜態設定(cell、E2 識別、SON 開關) | 只讀 |
| I-3 | `ScenarioController/run` | **啟動**一場:人數、時長、seed、SON 開關、預排事件 | **唯一可寫的介面** |
| I-4 | `RunReader/status` | 跑到哪、事件消化狀況 | 只讀 |
| I-5 | RIC 閘道 `GET /v1/scenarios/{run_id}/observation` | 觀測資料(KPM / 鄰區 / 關係表) | 只讀,**在 RIC 端不在 DT** |
| I-6 | `RunReader/events` | 事件紀錄(量測、換手、RLF、重建、CGI 解析) | 只讀 |
| I-7 | `RunReader/config_changes` | 誰在何時改了什麼(Agent 事件 / RIC 控制 / gNB 自主) | 只讀 |

## 零、多 gNB 的識別規則(先讀這節)

- **一個 gNB = 一個 CU = 一個 E2 node**。gNB 底下可以有多個 DU,cell 掛在 DU 上;同一個 gNB 的 cell 共用一個 E2 node。
- 場域釘一個**區塊號** `e2_block`(1–15)。gNB 依 registry 順序拿 `e2_index` 0、1、2…,
  `slot = 16 × block + e2_index`,**gNB ID = `0xe00 | slot`**(22 bit),`meid = gnb_<MCC>_<MNC 3 位>_<gNB ID 6 位 hex>`。
  例:區塊 2 的走廊 → src `gnb_208_095_000e20`、nbr `…000e21`、mid `…000e22`。
- **NCI = gNB ID << 14 | local_cell_id**(36 bit,TS 38.300 §8.2)。**ncgi 字串 = `<PLMN 6 位>-<NCI 9 位 hex>`**,例 `208095-003884000`。
- 執行期 cell 名 = `<cell_tag>:<registry cell 名>`,cell_tag 是 gNB ID 後三位 hex,例 `e21:nbr`。
- 這些值**啟動前就算得出來**(I-1 / I-2 的 `e2_identities[]`),與執行期完全相同。
- RIC 閘道的 `nodeId` = **registry 的 gNB 名稱**(`src` / `nbr` / `mid`),不是 `cu`。兩個並行場景 nodeId 可以同名,靠 scenarioId + meid 區分。命令送到哪個 node:source 類欄位(來源 cell / UE)所屬的 node;target 類欄位可以指向別的 node(見手冊 §9)。
- 舊的共用節點 `gnb_208_095_000e00` 保留給 RIC 常駐 xApp,Agent 的場景不會用到。

## I-2 `FieldReader/config` —— 場域設定

**請求** `{"field_id": "scene-…"}`

**回應 `data`**(節錄,corridor24_08_16 實際值)
```json
{"field_id": "...", "name": "corridor24_08_16", "config_version": "…",
 "cells": [{"cell_id": "src", "ran_cell_id": "e20:src", "ran_name": "gnb_208_095_000e20", "gnb_id": "src",
            "ncgi": "208095-003880000", "nr_cell_identity": 59244544,
            "pci": 0, "arfcn": 633333, "band": "n78", "center_frequency_ghz": 3.5, "bandwidth_mhz": 40.0,
            "tx_power_dbm": 10.0, "position": {"x": 3.73, "z": -14.15, "h": 2.5},
            "antenna": {"azimuth_deg": 180.0, "tilt_deg": 0.0, "type": "tr38901", "rows": 1, "cols": 1},
            "administrative_state": "unlocked", "operational_state": "enabled",
            "energy_saving_state": "notEnergySaving", "ric_managed": true}],
 "e2_identities": [ "… 同 I-1 …" ],
 "neighbour_relations": [], "xn_links": [],
 "son": {"anr_auto_add": false, "anr_pci_lookup": false, "anr_cgi_fail_rate": 0.0},
 "unavailable_fields": ["neighbour_relations(場景未宣告;執行期 ANR 建立的關係見 I-5 當下觀測)", "space.junctions", "space.obstacles", "space.segments"]}
```
- `cells[].gnb_id` 是 **gNB 名稱**(= RIC 閘道 `nodeId`),`ran_name` 是該 cell 所屬 E2 node 的 meid。
- **cell 識別**:I-3 的 `target` / `source_ncgi` / `target_ncgi` 三種寫法都收 —— `cell_id`(`"src"`)、`ran_cell_id`(`"e20:src"`)、`ncgi`(`"208095-003880000"`)。
- **`son` 是這個場域實際生效的值**。2026-09-27 修正:以前沒設時報 `anr_auto_add: true`,但 gNB 實際預設是關,已改為如實回報。
- **`xn_links` 空**:Xn 由各 gNB 開場時自行建立(Xn Setup,TS 38.423 §8.4.1),不是場景宣告;是否有鄰區、能否換手看 I-5 關係表。
- **永遠沒有的**:UE 座標(設計決定,不進任何介面)。

## I-3 `ScenarioController/run` —— 啟動一場(唯一可寫)

請求、回應、事件表與 2026-09-23 版相同,只列差異:
- `son.anr_auto_add`:**開 = gNB 從量測自己學鄰區(含跨 gNB,經 Xn 建關係);關 = NRT 只由 xApp 或事件維護**。沒開又沒人加關係時,UE 跨 gNB 只能靠 RLF 後重建,**不會有換手**(第三場走廊實測:整場 0 次換手、340 次 RLF)。
- 事件 `target` 可寫任一 gNB 的 cell;`relation_change` 的來源與目標可以在不同 gNB(跨 gNB 關係)。
- 回應 `run_id` = RIC 閘道 `scenarioId`;RIC 端一場有 N 個 node(每 gNB 一個),各自一個 `gen`。

```json
{"field_id": "scene-…", "seed": 103, "duration_s": 1800,
 "son": {"anr_auto_add": true},
 "events": [{"type": "relation_change", "at_offset_s": 60,
             "params": {"action": "add", "source_ncgi": "e20:src", "target_ncgi": "208095-003884000"}}]}
```

## I-4 `RunReader/status`

> 2026-09-28:DT 內部場次狀態收成三種(idle / precomputing / running),上一次怎麼結束另存 `last_result`。
> 對外 `status` 值不變(running / pending / done / failed);`native_status` 改為三種之一,另附 `last_result`(done / stopped / failed)。

不變。`{"run_id"}` → `status`、`progress_s`、`duration_s`、`windows_available`(**只算這個 run_id 最後一次啟動**)、`events{…}`、`ue_names`。
場景被人為或外部中止時 `status=failed`、`native_status=stopped`、`error` 說明;這時 `ue_names` 取 I-3 回應的 `echo.ue_names`。

## I-5 觀測 —— 在 RIC 閘道

`GET /v1/scenarios/{run_id}/observation?format=raw|aggregated|both`(RIC 端提供)。多 gNB 下仍是**一場一份**(全場視角),cell 級與關係級每筆帶所屬 `nodeId` / `meid`;`controlTargets[]` 每個 node 一筆。
- cell 名在 ran_func 5 與 ran_func 6 **一致**(`e21:nbr`),數值 NCI 另放 `nci` / `ncgiStd`。
- 同一個 UE 在一個窗內可能被多個 node 服務過(跨 gNB 換手或重建),RIC 的 `crossNodeHandover` 就是這個意思,**含 RLF 後跨 gNB 重建**。

## I-6 `RunReader/events`

**請求** `{"run_id", "from"?: 秒, "to"?: 秒, "types"?: [...]}`
型別:`meas_report`、`ho_exe_succ`、`ho_exe_fail`、`ho_prep_fail`、`rlf`、`rrc_reestab_req`、`cgi_resolution`

**共通欄位**(多 gNB 新增):`node_id`(gNB 名稱)、`meid`、`ric_triggered`、`ric_label`、`ric_instance_id`。
**換手 payload**(多 gNB 新增):`ho_type` ∈ `intra-DU` / `inter-DU` / `Xn` / `NG`、`source_ncgi` / `target_ncgi`(ncgi 字串)、`ngap_id`(AMF UE NGAP ID,**跨 gNB 不變**,即 RIC `ueLevel[].ngapId`)。

```json
{"type": "ho_exe_succ", "offset_s": 56.5, "ts_iso": "2026-09-27T19:44:53.970+00:00",
 "gnb_id": "nbr", "cell_id": "nbr", "ue_id": "p10", "node_id": "nbr", "meid": "gnb_208_095_000e51",
 "ric_triggered": false, "ric_label": null, "ric_instance_id": null,
 "payload": {"target_cell_id": "src", "target_ncgi": "208095-003940000", "source_ncgi": "208095-003944000",
             "target_pci": 0, "trigger": "A3_TTT", "ho_type": "Xn", "ngap_id": 790647096,
             "cause": null, "cause_category": null, "mro_class": null}}
{"type": "rrc_reestab_req", "offset_s": 1.5, "node_id": "nbr", "meid": "gnb_208_095_000e51", "ue_id": "p04",
 "payload": {"reestablishment_cause": "T310_EXPIRY", "previous_pci": 0, "previous_ncgi": "208095-003940000",
             "previous_cell_id": "src", "target_cell_id": "nbr", "derived_from": "rlf"}}
```
- **跨 node 的移動有兩種**:換手(`ho_exe_succ` 且 `ho_type` = `Xn` / `NG`),以及 RLF 後在另一個 gNB 重建(`rrc_reestab_req` 的 `node_id` 與前一筆 `rlf` 不同)。判「跨 node」要兩種都看。
- `rrc_reestab_req` 屬於**落點 cell 所在的 node**(可能與 RLF 的 node 不同)。
- `ric_triggered=true` 的換手(RC 3-1 / 3-1-group / 節能趕人)帶 `ric_instance_id` 與 `ric_label`,與 RIC `control_audit` 同一組鍵。
- 換手被判 MRO(`mro_class` = `TooEarly` / `ToWrongCell`)時,事件類型是 `ho_exe_fail`,`cause` 例如 `HandoverToWrongCell`:換手本身執行了,但 UE 很快 RLF 並在別處重建(TS 38.300 §15.5.2.2)。

## I-7 `RunReader/config_changes`

**請求** `{"run_id", "from"?, "to"?, "origin"?: "triggered_event|son_function|system"}`

```json
{"offset_s": 2641.5, "origin": "son_function", "source": "son/anr_auto",
 "object_type": "neighbour_relation", "object_id": "e51:nbr>e50:src", "attribute": "exists",
 "before": "false", "after": "true", "action": "neighbour_relation_add", "outcome": "applied",
 "reason": "UE 量測報告回報了未建立關係的鄰區", "node_id": "nbr", "meid": "gnb_208_095_000e51",
 "ric_triggered": false, "ric_label": null, "ric_instance_id": null, "ric_requestor_id": null}
{"offset_s": 2961.5, "origin": "triggered_event", "source": "ric/CCC",
 "object_type": "cell", "object_id": "e51:nbr", "action": "control_cell_enable", "outcome": "ACK",
 "node_id": "nbr", "meid": "gnb_208_095_000e51", "ric_triggered": true,
 "ric_label": "<scenarioId>|nbr|g2|<label>", "ric_instance_id": 19, "ric_requestor_id": 1234,
 "unavailable_fields": ["before/after"]}
```
- `source` 前綴:`agent/*` = Agent 自己的 I-3 事件;`ric/*` = RIC/xApp 控制(`outcome` ACK / FAIL / pending);`son/*` = gNB 自主行為(ANR 自動加關係、CGI 解析、xApp 命令落地如 `son/ric_apply prb_quota_applied`)。
- **對帳**:`ric_label` = RIC 閘道改寫、經 E2AP RICcallProcessID(IE 20)帶到 RAN 的 `<scenarioId>|<nodeId>|g<gen>|<呼叫端 label>`;RIC `control_audit` 把四段分開存(scenario / nodeId / gen / label),對帳時拆四段逐一比。`ric_instance_id` / `ric_requestor_id` = E2AP RICrequestID(rc-probe 重啟後從 1 重來,要連 run 一起比)。
  **2026-09-27 以前的場次這三欄是空的**(稽核輸出漏欄,已修),那些場次請用 I-6 事件與時間對帳。
- 跨 gNB 的反向鄰區關係是**對方 gNB 經 Xn 自己建的**,記在對方 node 的 I-7 列,不在發起端。
