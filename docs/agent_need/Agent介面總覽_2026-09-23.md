# Agent 介面總覽(2026-09-23 現況)

Base URL:`http://<orchestrator>:8302/api/v0.1/Run_orchestrator/Agent_api/`,全部 **POST + JSON body**。
回應一律 `{"success": bool, "message": str, "data": {...}}`;錯誤時 `success=false`,`errors` 帶細節。
所有時間:`offset_s` = 自劇本起點的**劇本秒**(不是牆鐘);`ts_iso` 是對映出的牆鐘 UTC。

| 介面 | 端點 | 用途 | 能改什麼 |
|---|---|---|---|
| I-1 | `FieldReader/list` | 有哪些場域(劇本)可跑 | 只讀 |
| I-2 | `FieldReader/config` | 一個場域的完整靜態設定(cell、E2 識別、SON 開關) | 只讀 |
| I-3 | `ScenarioController/run` | **啟動**一場:人數、時長、seed、SON 開關、預排事件 | **唯一可寫的介面** |
| I-4 | `RunReader/status` | 跑到哪、事件消化狀況 | 只讀 |
| I-5 | RIC 閘道 `GET /v1/scenarios/{run_id}/observation?format=raw\|aggregated\|both` | 觀測資料(KPM / 鄰區 / 關係表) | 只讀,**在 RIC 端不在 DT** |
| I-6 | `RunReader/events` | 事件紀錄(量測、換手、RLF、CGI 解析) | 只讀 |
| I-7 | `RunReader/config_changes` | 誰在何時改了什麼(Agent 事件 / RIC 控制 / gNB 自主) | 只讀 |

## I-1 `FieldReader/list` —— 場域清單

**請求** `{"category": "corridor"}`(可選;`ready_only: true` 只列可立即啟動的;`all: true` 含未備妥)

**分類(`category`)**:目前資料裡只有兩種在用 —— **`corridor`(走廊)** 三場、`other`(室內測試 live 場)一場。`anr` / `intent` / `scale` 是預留值,尚無場域掛上。Agent 挑劇本**先以走廊/室內這個分類為主**,ANR 題型都是走廊場 + 事件製造出來的(見 I-3)。

**回應 `data.fields[]`**
```json
{"field_id": "scene-38eadee02bef4b92a25931f5688d5abe", "name": "corridor24_16_24",
 "category": "corridor", "category_inferred": false,
 "config_version": "405c36afe21f",           // I-3 可帶回來核對,變了會 409
 "cell_count": 3, "gnb_count": 3, "ue_count": 18,
 "load_profiles": [{"name": "corridor24_16_24", "default_ue_count": 18,
                    "mobility": "劇本寫定之路徑", "has_presence_windows": true}],
 "event_types": ["cell_outage","energy_saving_state","tx_power_change","relation_change","pci_change"],
 "event_param_schema": { "<type>": { "<param>": "說明" } },   // 照這個組 I-3 的 events[].params
 "coordinate_convention": "x 向右、z 向前、y 向上,單位公尺"}
```
可用場域(2026-09-23):

| name | category | cell / UE | 模式(倍速上限) | 可用事件 |
|---|---|---|---|---|
| corridor24_00_08 / 08_16 / 16_24 | **corridor** | 3 / 18 | cached(10x,實測約 4.7x) | 上述 5 種 |
| livetest_corridor | other(室內 live) | 4 / 18(含 1 顆備用) | live(2x) | 上述 5 種 + `cell_addition`、`antenna_change` |

 "cells": [{"cell_id": "src", "ran_cell_id": "e03:src", "ncgi": "208095-56bce6561", "nr_cell_identity": 23283524961,
            "pci": 0, "arfcn": 633333, "band": "n78", "center_frequency_ghz": 3.5, "bandwidth_mhz": 40.0,
            "tx_power_dbm": 10.0, "position": {"x": 3.73, "z": -14.15, "h": 2.5},
            "antenna": {"azimuth_deg": 180.0, "tilt_deg": 0.0},
            "administrative_state": "unlocked", "operational_state": "enabled",
            "energy_saving_state": "notEnergySaving", "ric_managed": true}],
 "neighbour_relations": [], "xn_links": [],        // 場景層未宣告;執行期 NRT 看 I-5
 "collection": {"granularity_period_s": 60, "timezone": "Asia/Taipei", "baseline_windows_required": 10, "clock_source": "simulated"},
 "e2_identity": {"e2_node_id": "gnb_208_095_000e03", "gnb_id": "0x000e03", "plmn": {"mcc": "208", "mnc": "095"},

## I-3 `ScenarioController/run` —— 啟動一場(唯一可寫)

**請求**
```json
{"field_id": "scene-…",                 // 必填
 "config_version": "405c36afe21f",      // 可選;與現況不符回 409
 "seed": 103,                           // 必填;同參數同 seed → 同結果
 "duration_s": 1800,                    // 必填;≥ 720(基準 10 窗 + 2 窗)
 "ue_count": 12,                        // 可選;只能 ≤ 場域人數(只減不增),取前 N 個 UE
 "load_profile": "corridor24_16_24",    // 可選;必須等於場域名(人流是寫定的)
 "magnitude": 1.0,                      // 收下但不作用(unavailable_fields 會註明)
 "requester_task_id": "任意字串",       // 純追溯
 "son": {"anr_auto_add": false, "anr_pci_lookup": true, "anr_cgi_fail_rate": 0.0},   // 可選,啟動時寫入、整場固定
 "events": [ ... ]}                     // 可選,預排事件(見下)
```
**`son` 三個開關**(沒帶就沿用 I-2 的現值)

| 欄位 | 預設 | 作用 |
|---|---|---|
| `anr_auto_add` | true | gNB 量到未知 PCI 時自動解析並寫 NRT。**false = 缺漏鄰區題的前提**(NRT 只由 xApp 或事件維護;RIC 端 guard 同步關) |
| `anr_pci_lookup` | false | 是否做 PCI→CGI 解析 |
| `anr_cgi_fail_rate` | 0 | CGI 解析隨機失敗率 0~1 |

**`events[]`** —— 啟動時全部宣告,排程器到劇本秒才執行;**沒有跑到一半再改的介面**
```json
{"event_id": "E1",                       // 可選,預設 E1、E2…
 "type": "relation_change",              // 見 I-1 event_types
 "at_offset_s": 60,                      // 劇本秒,≤ duration_s
 "duration_s": 300,                      // 可選;到期自動還原(outage/es/cell_addition/pci_change 支援)
 "target": "e03:src",                    // 作用 cell(relation_change 用 params 的 source/target)
 "params": { ... }}                      // 依型別,見 I-1 event_param_schema
```
| type | params | 效果 |
|---|---|---|
| `cell_outage` | `reason?` | DU 停排程 + RU 停發射 |
| `energy_saving_state` | `state_after: energySaving\|notEnergySaving` | 同上開關,成因不同 |
| `tx_power_change` | `tx_power_dbm_after` | RU 功率 + DU/CU 功耗輸入 |
| `relation_change` | `action: add\|remove\|set`, `source_ncgi`, `target_ncgi`, `attributes?{is_ho_allowed,is_remove_allowed,is_xn_allowed}` | CU NRT,與 xApp 同一入口 |
| `pci_change` | `pci_after` 0~1007 | 只改廣播 PCI 標籤(訊號不變)→ 設成與另一顆相同 = PCI 混淆 |
| `cell_addition` | `tx_power_dbm?` | 只能開「備用 cell」(walk-in 場域才有) |
| `antenna_change` | `tilt_deg_after`, `azimuth_deg_after` | **live 模式限定** |

**回應**(200)
```json
{"run_id": "scene_run-…",               // = I-4/6/7 的 run_id,也 = RIC 閘道的 scenarioId
 "instance_id": "SC-3af1ae09dd",        // 同參數決定性識別
 "status": "running", "started_at": "…Z", "estimated_finish_at": "…Z",
 "echo": {"ue_count": 18, "duration_s": 1800, "seed": 103, "mode": "cached", "speed_x": 10.0,
          "events": 2, "events_scheduled": 2, "son": {...}, "ue_names": ["p00", …]},
 "unavailable_fields": ["magnitude(…不作用)"], "notes": []}
```
錯誤:400 驗證(附 `supported_types` / `cells` / 每筆 `event_id` 的原因)、404 場域不存在、409 `config_version` 不符或該場域正在跑、503 RIC 閘道不在。

**ANR 題型怎麼用 I-3 製造**

| 題型 | 設定 |
|---|---|
| 缺漏鄰區 | `son.anr_auto_add=false`,可再加 `relation_change add`(60 s)→ `remove`(1200 s)造窗 |
| 錯誤/多餘鄰區 | `relation_change add` 一條實際收不到訊號的關係 |
| 關係旗標錯 | `relation_change set` + `attributes` |
| PCI 混淆 | `pci_change` 把一顆改成與另一顆相同的 PCI(A:auto_add=true 看 gNB 自主行為;B:false 交 xApp) |
| cell 停機/節能 | `cell_outage` / `energy_saving_state`(+`duration_s` 自動恢復) |

## I-4 `RunReader/status`

**請求** `{"run_id": "scene_run-…"}`
**回應** `{"status": "running|done|failed|stopped", "progress_s": 1476.0, "duration_s": 1800, "started_at", "finished_at",
"windows_available": 1525, "events": {"total": 1, "pending": 0, "alive": true, "deadline_s": 1800}, "ue_names": [...], "error": null}`
`status=done` = 劇本秒到 `duration_s` 由我方停止。

## I-5 觀測 —— 在 RIC 閘道

`GET /v1/scenarios/{run_id}/observation?format=raw|aggregated|both`(RIC 端提供、已上線)。
`aggregated` = 60 秒視窗統計(cell 級 KPM、鄰區量測彙整、關係表);`raw` = 一份 E2 報告一筆(約 0.5 s 一筆)。
鄰區在觀測裡以 **(pci, arfcn)** 為鍵,`ncgi` 只在 gNB 的 NRT 能唯一解出時才附;兩顆同 PCI 同時可見時會合併成一筆且**不附 ncgi**。

型別:`meas_report`、`ho_exe_succ`、`ho_exe_fail`、`ho_prep_fail`、`rlf`、`rrc_reestab_req`、`cgi_resolution`

{"type": "ho_prep_fail", ..., "payload": {"target_pci": 0, "trigger": "MANUAL", "cause_category": null, "mro_class": null}}

## I-7 `RunReader/config_changes`

**請求** `{"run_id", "from"?, "to"?, "origin"?: "triggered_event|son_function|system"}`
**回應 `data.changes[]`**
```json
{"offset_s": 302.0, "ts_iso": "…Z", "origin": "triggered_event", "source": "agent/pci_change",
 "object_type": "cell", "object_id": "e03:nbr", "action": "pci_change", "outcome": "applied",
 "before": null, "after": null, "reason": null}
```
`source` 前綴:`agent/*` = Agent 自己的 I-3 事件;`ric/*` = RIC/xApp 下的控制(`outcome` ACK / FAIL / pending);`son/*` = gNB 自主行為(CGI 解析、xApp 命令落地如 `son/ric_apply prb_quota_applied`)。
