## 一、`2-6` 限定 cell:走 **RAN Parameter,不是 Control Header**

貴方的判讀正確 —— **E2SM-RC Control Header Format 1 沒有 cell 欄位**,我方文件寫的 `control_header.cell_id` 是
**adapter → sim CU 的內部 HTTP 欄位**,不是 E2 IE。以前只有非 E2 的直呼路徑用得到,經 E2 進來的一律只有 node,
所以「CU 套到全 gNB」確實是唯一正確的解讀,run 45 那兩筆是 gNB 級沒錯。這個誤導是我方文件造成的,抱歉。

**已實作(下一場生效):`2-6` 新增選配 `ranP[4] = Target Cell(NR-CGI)`**,格式**與 `2-8` 的 `ranP[1]`、
`3-1` 的 Target Primary Cell ID 完全相同**(貴方 rc-probe 已經有這個 builder,直接複用即可):

```
ranP[1] = min_prb          valueInt      ← 不變
ranP[2] = max_prb          valueInt      ← 不變
ranP[3] = dedicated_prb    valueInt      ← 不變
ranP[4] = Target Cell      structure{ PLMN-Identity: valueOctS(6 hex), NR-Cell-Identity: valueBitS(36 bits) }
                                         ← 新增,選配
```

行為:
- **帶 ranP[4]** → 配額只套那一顆 cell;NCI 解不開回 **409 `target_cgi unresolved`**(不會默默套到全 gNB)。
- **不帶** → 維持現況,套整個 gNB 的所有 active cell。
- 解析時 `ranP[4]` 不會被當成配額數值(我方只取 id 1–3 的 valueInt),所以**舊 builder 送三個參數完全不受影響**。

`target_nci` 的取值與 `3-1` / `2-8` 同源:DT 的 I-2 `e2_identity.cells[].nr_cell_identity`(十進位)或
`nr_cell_identity_hex`;PLMN 用 `02f859`。

貴方 0.1.2 把 label 改成 `exec-prb-gnb-<觸發cell>-<ue>`、證據帶 `scope` 與 `triggerCell` —— 這樣就誠實了,
之後要縮到單顆再帶 ranP[4] 即可。
