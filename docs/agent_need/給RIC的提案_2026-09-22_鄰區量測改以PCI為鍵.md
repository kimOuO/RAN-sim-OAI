# 提案(請 RIC 評估):ran_func 5 逐 UE 的鄰區量測改以 PCI@ARFCN 為鍵,不再暴露 cell 身分

日期:2026-09-22 · DT 端 · 狀態:**提案,尚未改動**,等貴方回覆後排協調窗口

## 一、問題

現在 ran_func 5 逐 UE 的鄰區量測長這樣:

```json
"neighbors": [{"e03:mid": {"pci": 2, "arfcn": 633333, "rsrp": -62.1, "rsrq": -31.0}}]
"all_rsrp":  {"src": -52.3, "mid": -62.1, "nbr": -70.4}
```

鍵是 cell 身分(`e03:mid`、gNB 名)。**真實 UE 的量測報告只有 PCI + 載波頻率 + RSRP/RSRQ**,gNB 要知道那個 PCI 是哪顆 cell,得先下 ReportCGI 讓 UE 去讀 SIB1。我們把身分直接當鍵送出,等於把「缺漏鄰區」「PCI 混淆」這兩類題型的答案印在題目上 —— Agent 的 xApp 不需要解任何東西就知道 PCI 2 是 `e03:mid`。這與我方今天決定 UE 座標不送的原則相同:**模擬器不該把真實 RAN 拿不到的東西混進觀測**。

## 二、提案的形狀

```json
"neighbors": [
  {"pci": 2, "arfcn": 633333, "rsrp": -62.1, "rsrq": -31.0, "ncgi": "208095-db8cf0c57"},
  {"pci": 1, "arfcn": 633333, "rsrp": -70.4, "rsrq": -35.2}
]
"all_rsrp":  [{"pci": 0, "arfcn": 633333, "rsrp": -52.3, "serving": true}, {"pci": 2, "arfcn": 633333, "rsrp": -62.1}, …]
```

- 由 dict 改為 list,每筆以 `pci` + `arfcn` 識別。
- **`ncgi` 只在 CU 的鄰區表(NRT)已解出該 PCI 對應的 CGI 時才附**;沒解出就沒有這個鍵。這正是真實 gNB 知道的程度:PCI 在 NRT 裡 → 知道是誰;不在 → 不知道,要走 CGI 回報(我方 ran_func 6 的 `cgi_resolution` 事件)。
- PCI 混淆(同 PCI 對到兩顆)時 `ncgi` 亦不附,並在 ran_func 6 以既有 `confused` 事件呈現。
- 服務 cell 的 `ncgi` 照常給(gNB 當然知道自己是誰)。

## 三、對貴方的影響

| 貴方元件 | 影響 |
|---|---|
| `dt_fullkpm.ue_neighbor` | 目前以 cell 名為標籤;需改為 `pci` + `arfcn`,`ncgi` 為可選欄位 |
| `dt_preproc.meas_report_agg`(按 `cell` / `reportedPci`) | `reportedPci` 已存在,`cell` 改為「有 ncgi 才填」 |
| `observation.e2MessageCopyAggregate.measurementReportAggregate` | 規格本來就是 `reportedPhysicalCellId` / `reportedArfcn`,反而更貼近 |
| 貴方 `control_selftest` 推導 anr-add 目標 | 目前若從 neighbors 鍵拿 cell 名,需改從 ncgi(有時)或走 rc-reportcgi 解 |

## 四、切換方式(建議)

我方以 env `E2_NEIGHBOR_KEY=pci`(預設 `cell`,維持現況)實作,程式先上、開關關著;貴方 preproc 準備好後約一個窗口同時切。切換後舊格式不再送。

## 五、請回覆

1. 接不接受改以 PCI 為鍵、`ncgi` 條件式附帶。
2. 貴方需要多久調整 `ue_neighbor` / `meas_report_agg`。
3. 是否需要一段雙格式並送的過渡期(我方可同時送 `neighbors`(新)與 `neighbors_legacy`(舊)兩週)。
