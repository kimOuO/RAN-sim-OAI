# 給 RIC 的回覆：I-5 觀測資料統一由閘道提供、DT 端已補齊的欄位

日期：2026-09-22　對象：RIC 團隊　主題：Agent 需求規格 I-5 的分工，以及貴方指南「還沒有的」清單更新

## 一、結論：I-5（觀測資料）全部由 RIC 閘道提供，DT 不另開觀測介面

看過貴方的《給 Agent 與新 xApp 的使用指南》後，`GET /v1/scenarios/{id}/observation` 已經是規格 §I-5 `aggregated` 的形狀，且鄰區關係、逐關係換手統計、量測報告彙整、重建反推四個子表都有。DT 若再從歸檔重算一份，兩套基準算法會給 Agent 兩個不同的數字，因此 DT **不做** aggregated。

為了讓 Agent 的觀測只有一個入口，**raw 也請放在閘道**（見第二節）。分工如下：

| 介面 | 提供方 | 說明 |
|---|---|---|
| I-1 場域清單、I-2 場域配置、I-3 觸發情境、I-4 執行狀態 | DT | 場域、觸發、事件注入，RIC 無此資訊 |
| **I-5 觀測（aggregated + raw）** | **RIC 閘道** | 本文主題 |
| I-6 事件紀錄、I-7 組態變更紀錄 | DT | 換手失敗原因、RLF 明細、DT 自主行為（ANR 自動建立等）只在 DT 端 |

一句話給 Agent：**「要跑什麼、發生了什麼」問 DT；「量到什麼」問 RIC。**

## 二、請貴方補：raw 巢狀輸出（規格核心要求之二）

規格開頭四項核心要求的第二項：「觀測資料分彙整觀測與原始觀測兩種格式，原始觀測須含每終端量測（含鄰區量測）與 cell 級量測」；§I-5 並註明「結構依先前 E2 範例，請沿用」。這正是貴方指南「五、還沒有的」第二項。原料貴方已有（`dt_fullkpm` 逐 UE 列 + `cell_level`），劇本時間在 `window_meta.scene_t_start/end`。

建議形狀（即 DT 的 E2FullReporter 輸出，Agent 已看過）：

```
GET /v1/scenarios/{id}/observation?format=raw&run=…&from=<scene_t>&to=<scene_t>&page_size=30&next_token=…
{
 "scenarioId", "run", "scene", "granularityPeriod": "60s",
 "windows": [
  {"offset_s": <劇本秒>, "timestamp": <epoch 秒>, "timestamp_iso": "…",
   "e2": [{"gnb_id": "src", "cells": [{"cell_id": "e03:src", "ncgi": "…", "pci": 0,
            "ues": [{"ue_id": "p11", "rsrp": -52.3, "rsrq": -27.3, "sinr": 18.1, "ul_sinr": 20.4, "cqi": 13,
                     "neighbors": [{"e03:mid": {"pci": 2, "arfcn": 633333, "rsrp": -62.1, "rsrq": -31.0}}],
                     "dl_throughput": 96.2, "ul_throughput": 4.1, "rb_width": 106}]}]}],
   "pm": {"src": [{"cell_id": "e03:src", "du_RRU.PrbTotDl": "46", …全部鍵…}]}}
 ],
 "next_token", "unavailable_fields"
}
```

- `offset_s` 用劇本時間（`sceneSimMs`），與 DT 的 I-6 事件、I-7 組態變更同一條時鐘，Agent 才能做「第 N 秒注入事件後觀測怎麼變」的對照。
- `ues[]` 缺 `role`、`interfered`、`rb_start`、`position`（DT 沒有），請列入 `unavailable_fields`，勿補 0。
- `format=both` 一次回兩種亦可。

## 三、貴方指南中已過時的「DT 尚未提供」

以下欄位 **2026-09-22 起已在 ran_func 5 上**，請 preproc 撈入：

| 欄位 | 鍵名 | 說明 |
|---|---|---|
| 傳輸區塊計數 | `du_TB.TotNbrDl`、`du_TB.TotNbrDl.Tot`、`du_TB.ErrTotalNbrDl`、`du_TB.ErrTotalNbrDl.Tot`（UL 同名） | 上下行分離；⚠ 由 SINR 分箱估算，方向與量級可用，不宜做嚴格 BLER 校驗 |
| cell 可用率 | `du_gnb.PEE.cellAvailablePer` | 運作 tick ÷ 存在期間 tick；實測關站後由 99.9% 降至 48.6% |
| 功耗 | `du_gnb.PEE.AvgPower`（W）、`du_gnb.PEE.Energy`（kWh，**累計值**，取區間請做差分） | ETSI ES 203 228 線性模型；低功率場域靜態功耗主導，數值變動小是物理結果 |
| E2 Setup 的 `servedNrCells` | — | 已改送真正的 F1AP F1SetupRequest，R-NIB 應可解出 cell 數（先前為自訂 TLV） |

## 四、識別對應（給 Agent 文件用，請確認）

| 對象 | RIC 側 | DT 側 |
|---|---|---|
| 場景 | `scenarioId` = `scene_run-…` | I-3/I-4 的 `run_id`（同值） |
| 場次 | `run` | DT 歸檔的 `ric_run`（同值）；DT 自己另有 `run_seq` 僅內部用 |
| 劇本 | `labels.scene_name` | I-1 的 `name` / `load_profile` |
| cell | `e03:src`（帶 E2 槽位標籤） | I-2 的 `e2_identity.cells[].cell_id`（同值）；I-2 主鍵 `cell_id` 為 `src`、`ncgi` 另列 |

DT 的 I-3 對 `target` 同時接受 `src`、ncgi 與 `e03:src`，三種都可。

## 五、其他請知悉

- live 模式倍速上限 2x（cached 不限）；同一場域同時只跑一場。
- DT 側 cached 30x 下 run 起始約 60 秒內，同一劇本秒可能出現 2～3 個 PM 視窗（DU 起始段序號與劇本時鐘不同步，DT 追查中）；貴方 `window_meta.reason=warmup` 已把前幾窗排除在基準外，應不受影響。
- 請回覆：raw 是否由貴方補、預計時程；第三節欄位撈入後是否還缺。
